## 1. Executive Summary

### 1.1 Project Vision

The AI Decision Intelligence Engine (ADIE) is a **domain-general**, deterministic, structured decision-making system. It handles any decision involving choice under uncertainty, multiple stakeholders, and conflicting interests:

- **Relationships:** "Which of three potential partners should I pursue?" "How do I respond to conflict with my partner?"
- **Career/Business:** "Take the risky new opportunity or stay?" "Accept, counter, or reject this offer?"
- **Purchases:** "Buy product A, B, or neither?"
- **Negotiations:** "Accept their terms, counter, or walk away?"
- **Life forks:** "Move cities? End the relationship? Make the big change?"

**Core Philosophy:** LLMs are interview facilitators and parsers. All decision logic is programmatic, deterministic, and grounded in validated research. Every claim entering calculations is classified, sourced, and confidence-scored.

### 1.2 The v3.3 Innovations

v3.3 closes the gap between *detection* (v3.2: catching assumptions/biases after they occur) and *prevention* (v3.3: ensuring claims are properly grounded before they're used):

**Innovation 1: Validated Framework Library** — A curated database of ~45 research frameworks drawn from the full body of literature underpinning this engine. Each entry specifies what the framework supports, what it does NOT support (preventing misapplication), applicable domains, and confidence. Any claim citing a framework is verified against the library.

**Innovation 2: Claim Classification System** — Every claim is classified into one of six epistemic categories (Validated Research → User Validated → Practitioner Heuristic → Probability-Weighted → Hypothesis → Speculation). Only claims meeting confidence thresholds enter calculations.

**Innovation 3: Emergent Discovery Validation** — The five discovery strategies (counterfactual, perspective reversal, temporal shifting, constraint removal, analogical reasoning) each have per-strategy grounding rules, generalized for any domain.

**Innovation 4: Expected Value Enforcement** — Uncertain outcomes must be probability-weighted. Treating contingent value as guaranteed is automatically rejected (prevents "equity as salary" framing errors across any domain — contingent bonuses, uncertain relationship outcomes, conditional deals).

**Innovation 5: Base Rate Database** — Lookup system for validated statistics. Returns "not found" rather than allowing fabrication. Expandable, domain-general.

**Innovation 6: System-Level Bias Detector** — Devil's Advocate for LLM outputs. Detects plausibility bias, fabricated specificity, prescriptive-as-descriptive, and completeness illusion in system-generated content.

**Innovation 7: Session Closing Protocol** — Every interview session ends with three-level open-ended questions (self, each stakeholder, situation) to surface information the system didn't ask about.

### 1.4 Design Principles (Complete, v3.3)

1. **Domain-General:** Every component works for any decision type — no startup-specific, career-specific, or negotiation-specific hardcoding
2. **Emergent Questioning:** Questions generated from design tree frontier, never predetermined
3. **Validated Translation:** Every number entering calculations is properly translated with confidence scoring
4. **Bias-Challenged Answers:** User answers stress-tested against nine cognitive biases
5. **Zero Assumptions:** No inference enters calculations without user confirmation or clear evidence
6. **Framework-Grounded Claims:** Every research-based claim verified against validated library
7. **Classified Epistemics:** Every claim sorted by evidentiary strength; speculation cannot enter calculations
8. **Probability-Weighted Values:** Uncertain outcomes never treated as certain
9. **Honest Statistics:** Base rates come from database or cited source — never fabricated
10. **System Self-Scrutiny:** LLM outputs checked for fabrication and bias, not just user inputs
11. **Completeness via Closure:** Open-ended closing questions surface what the system didn't ask
12. **Facts vs. Decisions:** LLM answers facts; user answers decisions
13. **Determinism First:** All decision calculations are programmatic algorithms
14. **Persistent Context:** User profiles and history stored locally, searchable
15. **Full Explainability:** Every recommendation traceable through comprehensive audit trail

## 4. The Emergent Grilling Protocol

### 4.1–4.5 Core Protocol

*(Unchanged from v3.2 — design tree, frontier, rounds, facts vs. decisions, termination as specified)*

### 4.6 Master System Prompt (v3.3)

```
# ROLE
You are the Grilling Agent in a Deterministic, Domain-General Decision Engine.
You conduct structured interviews using the grilling protocol, with full
validation: Translation, Devil's Advocate, Assumption Elimination, Claim
Classification, Framework Validation, Expected Value Enforcement, Base Rate
Verification, and System Bias Detection.

# THE PROTOCOL

## Design Tree
You model the subject as a design tree: every decision branches into the
decisions that hang off it. Your job is to interview until nothing is left
silently assumed — then run the Session Closing Protocol (see below).

## Frontier Calculation
Each round, you:
1. Identify all decisions whose prerequisites are settled
2. Generate questions for ALL of them (the frontier)
3. Never ask a question that depends on an unsettled question
4. Two questions never share a round if one depends on the other

## Question Format
❓ [number]: [Title]
[Question body specific to this decision context]
➡️ Recommended: [Your best answer based on available context]

## Facts vs. Decisions
- FACTS: You answer these yourself — but ONLY with CONTEXT or FRAMEWORK
  citation. Any framework you cite must come from the Validated Framework
  Library, and your claim must match what that framework actually supports.
- DECISIONS: These require user input. Mark as USER_INPUT_REQUIRED.

## Claim Classification (MANDATORY for every claim you make)
Before stating any claim, classify it:
- VALIDATED_RESEARCH: Cited from Framework Library, claim matches supported claims
- USER_VALIDATED: Confirmed by user with source
- PRACTITIONER_HEURISTIC: Common advice, not research-backed — must label as such
- PROBABILITY_WEIGHTED: Calculation with cited probability basis
- HYPOTHESIS: Speculation framed as hypothesis, cannot enter calculations
- SPECULATION: Anything else — REJECTED, do not state

## Framework Rules
- Cite frameworks ONLY from the Validated Framework Library
- Check "supports" list — does the framework actually support YOUR claim?
- Check "does_not_support" list — are you misapplying it?
- If no framework in the library supports your claim, say so honestly:
  "I don't have a validated framework for this. Treat as hypothesis."

## Expected Value Rule
Never treat uncertain/contingent outcomes as guaranteed:
- Contingent bonuses, equity, conditional promises, uncertain relationship
  outcomes → must be probability-weighted
- Required: P(outcome) with cited basis (Base Rate Database or user estimate)
- NEVER state "X is worth $Y" when Y is contingent — state expected value

## Base Rate Rule
Never generate statistics from memory:
- Any percentage, rate, or "X% of people/companies/situations..." claim
  → must come from Base Rate Database or cited source
- If not in database: "I don't have validated data for this rate."

## Counterparty Information
NEVER assume what other parties think, feel, fear, or want.
ALWAYS ask: "How do you know this?" / "Did they say this directly?"
Log source for every counterparty claim.

## Devil's Advocate
After user answers, check for: anchoring, loss aversion, social desirability,
overconfidence, status quo bias, sunk cost, confirmation bias, framing effect,
catastrophizing. Challenge when detected.

## Leverage Awareness
During interviews, look for: undervalued BATNA, unrecognized scarcity,
time asymmetry blindness, dependency misreading, information asymmetry
unawareness, network position blindness. Hidden leverage requires evidence —
do not assume counterparty constraints to "detect" leverage.

## Session Closing Protocol (when frontier is empty)
Before ending any session, ask three levels of open-ended questions:
1. SELF: "Is there anything about yourself, your situation, your preferences,
   or your constraints that we haven't discussed?"
2. EACH STAKEHOLDER: "Is there anything about [stakeholder] that we haven't
   discussed but might be relevant?"
3. SITUATION: "Is there anything about the overall situation — timing, context,
   external factors — that we haven't covered?"
If new information surfaces, re-open the design tree.

## Rounds
- Ask the ENTIRE frontier in one round
- Update the design tree based on answers
- Recalculate the frontier
- Repeat until frontier is empty AND closing protocol confirms completeness
- The number of rounds is EMERGENT, not fixed

# EPISTEMIC HALT PROTOCOL
<<<HALT>>>
PHASE: [1|1.5|2|3]
ROUND: [N]
BLOCKING_NODE: [the question]
WHY_BLOCKED: [why CONTEXT, FRAMEWORK, and validated BASE RATES cannot resolve this]
IMPACT_IF_ASSUMED: [how the tree would be corrupted by guessing]
USER_QUESTION:
❓ 1: [Title]
[Question in plain language]
➡️ Recommended: [Tentative answer + confidence: LOW/MEDIUM]
<<<END_HALT>>>

# FORBIDDEN
- Predetermined question lists
- Generic questions not specific to this decision
- Citing frameworks not in the Validated Framework Library
- Citing frameworks for claims they don't support
- Generating statistics without database or source
- Treating contingent outcomes as guaranteed
- Assuming counterparty psychology without user validation
- Making any claim without classifying it first
- Capping questions or rounds
- Ending a session without the Closing Protocol
```

## 8. Validated Framework Library

### 8.1 Overview

The Framework Library is the engine's **grounding layer** — the single source of truth for what research actually says. Every framework cited anywhere in the system (LLM reasoning, leverage detection, bias challenges, utility calculations) must exist in this library, and the claim being made must match what the framework supports.

**Key properties:**
- **Domain-general:** Frameworks organized by research domain, not by use case. "Power-Dependence Theory" applies to employer/employee, romantic partners, buyer/seller, friend/friend — any relationship with asymmetric dependence.
- **Supports AND does-not-support lists:** Prevents misapplication (the most common LLM failure mode — citing a real framework for a claim it doesn't make).
- **Living library:** Extensible. New frameworks added with full citation, supports/does-not-support lists, and domain tags. The library ships with the ~45 frameworks cited throughout this specification's development.

### 8.2 Library Schema

```python
@dataclass
class FrameworkEntry:
    id: str                          # e.g., "prospect_theory"
    citation: str                     # Full academic reference
    year: int
    domains: List[str]               # ["negotiation", "risk", "decision_making"]
    
    supports: List[str]              # Specific claims this framework validates
    does_not_support: List[str]       # Common misapplications
    
    confidence: str                  # "VERY HIGH" | "HIGH" | "MEDIUM-HIGH" | "MEDIUM"
    
    # Optional structured data some frameworks provide
    base_rates: Optional[Dict] = None        # For frameworks with empirical rates
    coefficients: Optional[Dict] = None      # For frameworks with numeric parameters
    measurement_instruments: Optional[List] = None  # For psychometric frameworks
    
    related_frameworks: List[str] = []       # IDs of related entries
```

    def __init__(self):
        self.frameworks = self.FRAMEWORKS
        self._build_semantic_index()
    
    def validate_claim(self, claim: str, cited_framework: str) -> 'FrameworkValidation':
        """
        Validates that a cited framework actually supports a specific claim.
        
        Returns FrameworkValidation with:
        - valid: bool
        - confidence: str  
        - matched_claim: the library entry the claim matches
        - reason: if invalid, why
        - suggestion: what to do instead
        """
        
        framework = self.frameworks.get(cited_framework)
        
        if not framework:
            return FrameworkValidation(
                valid=False,
                reason=f"Framework '{cited_framework}' not in validated library",
                suggestion="Use only frameworks from the library, or state claim "
                          "as hypothesis without framework citation"
            )
        
        # Check supports list (semantic matching in production;
        # keyword/embedding similarity)
        for supported_claim in framework.supports:
            if self._semantic_match(claim, supported_claim):
                return FrameworkValidation(
                    valid=True,
                    confidence=framework.confidence,
                    matched_claim=supported_claim,
                    framework_id=cited_framework,
                    citation=framework.citation
                )
        
        # Check does_not_support list (misapplication detection)
        for unsupported in framework.does_not_support:
            if self._semantic_match(claim, unsupported):
                return FrameworkValidation(
                    valid=False,
                    reason=f"MISAPPLICATION: Framework does NOT support this "
                           f"(matches: '{unsupported}')",
                    suggestion="Find appropriate framework, or reframe claim to "
                              "match what this framework actually supports"
                )
        
        # Neither matched — claim is unverified even if framework exists
        return FrameworkValidation(
            valid=False,
            reason=f"Framework '{cited_framework}' exists but claim doesn't match "
                   f"its supported claims",
            suggestion="Check library entry for what this framework supports, "
                      "or classify claim as hypothesis"
        )
    
    def find_frameworks_for_domain(self, domain: str) -> List[FrameworkEntry]:
        """Find all frameworks applicable to a decision domain"""
        return [
            fw for fw in self.frameworks.values()
            if domain in fw.domains
        ]
    
    def find_frameworks_for_claim(self, claim: str) -> List[FrameworkEntry]:
        """Find frameworks that might support a claim (for suggestion)"""
        candidates = []
        for fw in self.frameworks.values():
            for supported in fw.supports:
                if self._semantic_match(claim, supported, threshold=0.5):
                    candidates.append((fw, supported))
        return candidates
    
    def _semantic_match(self, claim: str, supported_claim: str, 
                        threshold: float = 0.7) -> bool:
        """
        Semantic similarity check between claim and library entry.
        Production: embedding similarity. Reference implementation: 
        keyword overlap + embedding fallback.
        """
        # Reference implementation (production uses embeddings)
        claim_words = set(claim.lower().split())
        supported_words = set(supported_claim.lower().split())
        
        if not claim_words or not supported_words:
            return False
        
        overlap = len(claim_words & supported_words)
        jaccard = overlap / len(claim_words | supported_words)
        
        return jaccard >= threshold
    
    def _build_semantic_index(self):
        """Build embedding index for fast semantic matching (production)"""
        pass

│  FRAMEWORK CITATION RULES (Enforced System-Wide)           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  RULE 1: Library-only citation                               │
│  Any FRAMEWORK-basis claim must cite a framework ID that    │
│  exists in the library. Unknown citation → rejected.        │
│                                                              │
│  RULE 2: Support verification                                │
│  The claim must semantically match an entry in the cited    │
│  framework's `supports` list. No match → rejected.          │
│                                                              │
│  RULE 3: Misapplication detection                            │
│  If the claim matches a `does_not_support` entry → reject   │
│  with explanation of the misapplication.                    │
│                                                              │
│  RULE 4: Honest gaps                                         │
│  If no framework in the library supports the claim, the     │
│  system must say: "I don't have a validated framework for   │
│  this." The claim can still be made as HYPOTHESIS (low      │
│  confidence, excluded from calculations) or PRACTITIONER    │
│  HEURISTIC (if explicitly labeled).                         │
│                                                              │
│  RULE 5: Domain relevance check                              │
│  The cited framework's `domains` list should include the    │

│  allowed but flagged (e.g., using organizational theory     │
│  for a personal relationship — plausible, needs care).      │
│                                                              │
│  RULE 6: Library extensibility                               │
│  New frameworks CAN be added to the library, but only with: │
│  - Full academic citation                                    │
│  - Curated supports / does_not_support lists                 │

## 9. Claim Classification System

### 9.1 The Six Categories

```python
class ClaimClassification(Enum):
    VALIDATED_RESEARCH = "validated_research"
    USER_VALIDATED = "user_validated"
    PRACTITIONER_HEURISTIC = "practitioner_heuristic"
    PROBABILITY_WEIGHTED = "probability_weighted"
    HYPOTHESIS = "hypothesis"
    SPECULATION = "speculation"


@dataclass
class ClassifiedClaim:
    claim: str
    classification: ClaimClassification
    confidence: float
    can_enter_calculations: bool
    framework_citation: Optional[str] = None
    user_source: Optional[str] = None
    probability_basis: Optional[str] = None
    disclosure_required: Optional[str] = None
    reason: Optional[str] = None


class ClaimClassifier:
    """
    Classifies every claim by epistemic status.
    Only claims with can_enter_calculations=True feed the
    deterministic layers (utility, minimax, leverage).
    """
    
    # Category definitions
    CATEGORIES = {
        ClaimClassification.VALIDATED_RESEARCH: {
            "description": "Supported by peer-reviewed research in library",
            "requires": "Framework citation + support match (§8)",
            "confidence_range": (0.80, 1.0),
            "can_enter_calculations": True,
            "example": "Having alternatives improves negotiation position "
                       "(Fisher & Ury, 1981 — batna_theory)"
        },
        
        ClaimClassification.USER_VALIDATED: {
            "description": "Fact confirmed by user with source",
            "requires": "User confirmation + source citation",
            "confidence_range": (0.70, 0.95),
            "can_enter_calculations": True,
            "example": "'My client has a board meeting in 2 weeks' "
                       "(user knows: recruiter told them)"
        },
        
        ClaimClassification.PRACTITIONER_HEURISTIC: {
            "description": "Common advice from practitioners, not research-validated",
            "requires": "Explicit labeling as practitioner advice",
            "confidence_range": (0.40, 0.60),
            "can_enter_calculations": True,  # With reduced weight
            "must_disclose": "This is practitioner advice, not research-backed",
            "example": "'Never accept a first offer' — common negotiation "
                       "advice; related research (Babcock et al.) supports "
                       "negotiating but not the 'never' prescription"
        },
        
        ClaimClassification.PROBABILITY_WEIGHTED: {
            "description": "Calculation involving uncertain outcomes",
            "requires": "Probability estimate + cited basis (base rate DB or user)",
            "confidence_range": (0.50, 0.80),
            "can_enter_calculations": True,
            "must_disclose": "Probability estimate based on [source]",
            "example": "'Expected value of this contingent bonus = "
                       "0.60 × $20k = $12k' (probability from user estimate "
                       "or base rate)"
        },
        
        ClaimClassification.HYPOTHESIS: {
            "description": "Speculation requiring testing; cannot enter calculations",
            "requires": "Explicit framing as hypothesis",
            "confidence_range": (0.20, 0.40),
            "can_enter_calculations": False,
            "must_disclose": "This is a hypothesis, not established fact",
            "example": "'Perhaps you could negotiate better terms' — "
                       "plausible but unverified for this situation"
        },
        
        ClaimClassification.SPECULATION: {
            "description": "Unverified claim; automatically rejected",
            "requires": "Nothing — this category exists to be rejected",
            "confidence_range": (0.0, 0.20),
            "can_enter_calculations": False,
            "system_action": "REJECT — cannot be used or stated as fact",
            "example": "'Negotiating equity from 0.5% to 1.0% is common' "
                       "(no source, no framework, fabricated statistic)"
        }
    }
    
    def classify(self, claim: str, 
                 cited_framework: Optional[str] = None,
                 user_validated: bool = False,
                 user_source: Optional[str] = None,
                 probability_basis: Optional[str] = None,
                 practitioner_labeled: bool = False) -> ClassifiedClaim:
        """
        Classify a claim through the full validation chain.
        """
        
        # Path 1: User-validated facts (highest priority for facts)
        if user_validated and user_source:
            return ClassifiedClaim(
                claim=claim,
                classification=ClaimClassification.USER_VALIDATED,
                confidence=0.85,
                can_enter_calculations=True,
                user_source=user_source
            )
        
        # Path 2: Framework-validated research
        if cited_framework:
            validation = self.framework_library.validate_claim(claim, cited_framework)
            if validation.valid:
                confidence = self._confidence_from_string(validation.confidence)
                return ClassifiedClaim(
                    claim=claim,
                    classification=ClaimClassification.VALIDATED_RESEARCH,
                    confidence=confidence,
                    can_enter_calculations=True,
                    framework_citation=cited_framework
                )
            else:
                # Framework cited but doesn't support claim
                # → falls through to lower categories with rejection note
                pass
        
        # Path 3: Probability-weighted claims
        if probability_basis:
            # Check basis is valid (base rate DB or user estimate)
            if self._valid_probability_basis(probability_basis):
                return ClassifiedClaim(
                    claim=claim,
                    classification=ClaimClassification.PROBABILITY_WEIGHTED,
                    confidence=0.65,
                    can_enter_calculations=True,
                    probability_basis=probability_basis,
                    disclosure_required=f"Probability based on: {probability_basis}"
                )
        
        # Path 4: Labeled practitioner heuristic
        if practitioner_labeled:
            return ClassifiedClaim(
                claim=claim,
                classification=ClaimClassification.PRACTITIONER_HEURISTIC,
                confidence=0.50,
                can_enter_calculations=True,
                disclosure_required="Practitioner advice, not research-backed"
            )
        
        # Path 5: Check if claim contains statistics/rates without basis
        if self._contains_unsourced_statistics(claim):
            return ClassifiedClaim(
                claim=claim,
                classification=ClaimClassification.SPECULATION,
                confidence=0.10,
                can_enter_calculations=False,
                reason="Contains statistics without cited source"
            )
        
        # Path 6: Check if claim asserts certain value for contingent outcome
        if self._treats_contingent_as_certain(claim):
            return ClassifiedClaim(
                claim=claim,
                classification=ClaimClassification.SPECULATION,
                confidence=0.10,
                can_enter_calculations=False,
                reason="Contingent outcome treated as certain (violates EV rule §11)"
            )
        
        # Default: hypothesis
        return ClassifiedClaim(
            claim=claim,
            classification=ClaimClassification.HYPOTHESIS,
            confidence=0.30,
            can_enter_calculations=False,
            reason="No framework citation, user validation, or probability basis"
        )
```

### 9.3 Calculation Gate

```python
class CalculationGate:
    """
    The final gate: only classified claims with sufficient confidence
    and can_enter_calculations=True may feed deterministic layers.
    """
    
    MIN_CONFIDENCE_FOR_CALCULATIONS = 0.50
    
    def check(self, classified_claim: ClassifiedClaim) -> 'GateResult':
        
        if not classified_claim.can_enter_calculations:
            return GateResult(
                allowed=False,
                reason=f"Classification {classified_claim.classification.value} "
                       f"cannot enter calculations"
            )
        
        if classified_claim.confidence < self.MIN_CONFIDENCE_FOR_CALCULATIONS:
            return GateResult(
                allowed=False,
                reason=f"Confidence {classified_claim.confidence} below "
                       f"threshold {self.MIN_CONFIDENCE_FOR_CALCULATIONS}"
            )
        
        # Claims entering calculations carry their classification forward
        # so the audit trail shows provenance
        return GateResult(
            allowed=True,
            classification=classified_claim.classification,
            confidence=classified_claim.confidence,
            provenance=self._build_provenance(classified_claim)
        )

                          user_evidence: Optional[str] = None) -> 'DiscoveryValidation':
        """
        Validates a discovery claim against its strategy's rules.
        """
        
        rules = self.STRATEGY_RULES.get(strategy)
        if not rules:
            return DiscoveryValidation(valid=False, reason="Unknown strategy")
        
        # Check classification is allowed for this strategy
        allowed_types = [ct["type"] for ct in rules["allowed_claim_types"]]
        if classification.classification.value not in [t.lower() for t in allowed_types]:
            if classification.classification == ClaimClassification.SPECULATION:
                return DiscoveryValidation(
                    valid=False,
                    reason=f"Claim is speculation — forbidden by {strategy}",
                    forbidden_rule=next(
                        (f for f in rules["forbidden"] 
                         if self._matches_forbidden(claim, f)), 
                        "matches forbidden pattern"
                    )
                )
        
        # Strategy-specific checks
        if strategy == "perspective_reversal":
            # Perspective claims about SPECIFIC counterparty need user evidence
            if self._asserts_specific_counterparty_psychology(claim):
                if not user_evidence:
                    return DiscoveryValidation(
                        valid=False,
                        reason="Asserts counterparty psychology without user evidence",
                        required_action="Ask user: 'What evidence do you have "
                                      "about their perspective?'"
                    )
        
        if strategy == "temporal_shifting":
            # Organization-specific temporal claims need user confirmation
            if self._asserts_specific_temporal_fact(claim):
                if not user_evidence:
                    return DiscoveryValidation(
                        valid=False,
                        reason="Asserts specific temporal fact without user confirmation",
                        required_action="Ask user to confirm this temporal detail"
                    )
        
        return DiscoveryValidation(valid=True, classification=classification)
```

## 11. Expected Value Enforcement

### 11.1 The Rule

> **Any value that is contingent on an uncertain outcome must be presented as an expected value (probability-weighted), never as a certain value.** This applies across ALL domains: contingent bonuses, equity, conditional promises, uncertain relationship outcomes, "if they say yes" scenarios, anything dependent on future events outside the user's control.

### 11.2 Implementation

```python
class ExpectedValueEnforcement:
    """
    Detects and rejects certain-treatment of contingent values.
    Domain-general: works on any contingent claim.
    """
    
    # Patterns indicating contingent value treated as certain
    # (linguistic patterns, domain-general)
    CONTINGENT_MARKERS = [
        "equity", "bonus if", "contingent on", "if they agree",
        "if it succeeds", "if we close", "should they accept",
        "upon signing", "upon success", "if the deal",
        "potential", "could be worth", "if it works out",
        "if they say yes", "assuming they", "provided that"
    ]
    
    CERTAINTY_MARKERS = [
        "is worth", "equals", "means you'll get", "adds up to",
        "total compensation", "that's a guaranteed", "you'll have"
    ]
    
    def check_claim(self, claim: str) -> Optional['EVViolation']:
        """
        Returns violation if claim treats contingent value as certain.
        """
        
        claim_lower = claim.lower()
        
        has_contingent = any(m in claim_lower for m in self.CONTINGENT_MARKERS)
        has_certainty = any(m in claim_lower for m in self.CERTAINTY_MARKERS)
        
        if has_contingent and has_certainty:
            # Extract the contingent value for correction
            contingent_value = self._extract_contingent_value(claim)
            
            return EVViolation(
                original_claim=claim,
                violation="Contingent value treated as certain",
                research_basis="prospect_theory — certainty effect; "
                              "von_neumann_morgenstern — expected utility",
                
                correction_prompt=f"""
                ❓ This claim treats a contingent value as guaranteed.
                
                "{claim}"
                
                The value "{contingent_value}" depends on an uncertain outcome.
                For honest analysis, we need:
                1. Estimated probability of the outcome (with basis)
                2. Expected value = P(outcome) × value
                3. Presentation as expected value, not certain value
                
                What's your probability estimate, and what's your basis?
                (Base Rate Database lookup available for common scenarios)
                """,
                
                required_action="Refuse claim until probability-weighted"
            )
        
        return None
    
    def compute_expected_value(self, value: float, probability: float,
                              probability_basis: str) -> 'ExpectedValueResult':
        """
        Computes properly-weighted expected value with audit trail.
        """
        
        if not 0.0 <= probability <= 1.0:
            raise ValueError(f"Invalid probability: {probability}")
        
        expected_value = value * probability
        
        return ExpectedValueResult(
            certain_value=value,
            probability=probability,
            probability_basis=probability_basis,
            expected_value=expected_value,
            classification=ClaimClassification.PROBABILITY_WEIGHTED,
            confidence=0.65 if probability_basis else 0.40,
            audit_note=f"EV = {probability} × {value} = {expected_value} "
                      f"(basis: {probability_basis})"
        )
```

## 13. System-Level Bias Detector

### 13.1 Overview

Devil's Advocate (§6) checks USER biases. The System Bias Detector checks **LLM-generated content** — the mirror-image safeguard.

### 13.2 The Four System Biases

```python
class SystemBiasDetector:
    """
    Detects biases in system/LLM-generated content.
    Runs on ALL LLM outputs before they enter the pipeline.
    """
    
    SYSTEM_BIASES = {
    
    "plausibility_bias": {
        "description": "LLM generates plausible-sounding but unverified claims",
        "detection_patterns": [
            "Confident assertion without citation",
            "Specific-sounding claim with no source",
            "Analysis presented as fact without classification"
        ],
        "action": "REQUIRE classification (§9) before use"
    },
    
    "fabricated_specificity": {
        "description": "Specific numbers/ranges/statistics without source",
        "detection_patterns": [
            r"\d+(?:\.\d+)?%",                                    # percentages
            r"\d+\s*(?:to|-)\s*\d+",                              # ranges  
            r"(?:common|typical|standard|usually|often)\s+\d+",   # "usually 3-5"
        ],
        "action": "REJECT unless from BaseRateDatabase (§12) or user-cited"
    },
    
    "prescriptive_as_descriptive": {
        "description": "Advice/should-statements framed as research findings",
        "detection_patterns": [
            r"(?:should|must|always|never)\s+(?:accept|reject|negotiate|ask|take|leave)",
            r"research shows (?:you |one )?(?:should|must|always|never)",
            r"(?:the key|secret|right way|best way) to",
        ],
        "action": "RECLASSIFY as PRACTITIONER_HEURISTIC with disclosure, or reject"
    },
    
    "completeness_illusion": {
        "description": "Analysis presented as complete/exhaustive when it isn't",
        "detection_patterns": [
            r"(?:all|every|complete|exhaustive|full) (?:factors|considerations|aspects)",
            r"(?:everything|nothing else) (?:to consider|matters)",
        ],
        "action": "FLAG: run Session Closing Protocol (§14) to check completeness"
    }
    }
    
    def check_output(self, llm_output: str) -> List['SystemBiasFlag']:
        """
        Check LLM-generated content for system biases.
        Returns flags for any detected issues.
        """
        
        flags = []
        
        # Check 1: Fabricated specificity
        for pattern in self.SYSTEM_BIASES["fabricated_specificity"]["detection_patterns"]:
            matches = re.findall(pattern, llm_output, re.IGNORECASE)
            for match in matches:
                # Check if this statistic has a source nearby
                if not self._has_nearby_source(llm_output, match):
                    flags.append(SystemBiasFlag(
                        bias_type="fabricated_specificity",
                        evidence=f"Statistic '{match}' without source",
                        action="Verify against BaseRateDatabase or remove",
                        severity="HIGH"
                    ))
        
        # Check 2: Prescriptive-as-descriptive
        for pattern in self.SYSTEM_BIASES["prescriptive_as_descriptive"]["detection_patterns"]:
            if re.search(pattern, llm_output, re.IGNORECASE):
                # Check if framed as research
                research_framing = re.search(
                    r"(?:research|study|data|evidence) (?:shows|finds|suggests)",
                    llm_output[:300], re.IGNORECASE
                )
                if not research_framing:
                    flags.append(SystemBiasFlag(
                        bias_type="prescriptive_as_descriptive",
                        evidence="Prescriptive advice without research framing",
                        action="Label as practitioner advice or remove",
                        severity="MEDIUM"
                    ))
        
        # Check 3: Plausibility bias (claims without classification)
        claims = self._extract_claims(llm_output)
        for claim in claims:
            if not self._has_classification_marker(claim):
                flags.append(SystemBiasFlag(
                    bias_type="plausibility_bias",
                    evidence=f"Unclassified claim: '{claim[:50]}...'",
                    action="Classify per §9 before use",
                    severity="MEDIUM"
                ))
        
        # Check 4: Completeness illusion
        for pattern in self.SYSTEM_BIASES["completeness_illusion"]["detection_patterns"]:
            if re.search(pattern, llm_output, re.IGNORECASE):
                flags.append(SystemBiasFlag(
                    bias_type="completeness_illusion",
                    evidence="Completeness claim without verification",
                    action="Run Session Closing Protocol",
                    severity="LOW"
                ))
        
        return flags
```

## 14. Session Closing Protocol

### 14.1 The Rule

> **Every interview session (Phase 1, Phase 1.5, Phase 3, and the User Profile interview) ends with three levels of open-ended questions before the session is considered complete.** An empty frontier means the system has no more generated questions — NOT that the user has shared everything.

### 14.2 The Three Levels

```python
class SessionClosingProtocol:
    """
    Open-ended closing questions at the end of every interview session.
    Three levels: Self, Each Stakeholder, Situation.
    If new information surfaces, the design tree re-opens.
    """
    
    LEVEL_1_SELF = (
        "Before we finish this part, is there anything about yourself — "
        "your situation, preferences, fears, constraints, goals, or anything "
        "we haven't discussed — that might be relevant to this decision?"
    )
    
    LEVEL_2_STAKEHOLDER_TEMPLATE = (
        "Is there anything about {stakeholder} — or your relationship with "
        "them — that we haven't discussed but might be relevant?"
    )
    
    LEVEL_3_SITUATION = (
        "Is there anything about the overall situation — timing, context, "
        "external factors, anything at all — that we haven't covered but "
        "could affect this decision?"
    )
    
    FOLLOW_UP_PROMPTS = [
        "Any concerns or fears we haven't addressed?",
        "Any information you're holding back or unsure whether to mention?",
        "Anyone affected by this decision we haven't identified?",
        "Any 'wild card' factors you're aware of?",
        "Anything that feels important but hasn't come up?"
    ]
    
    def conduct_closing(self, design_tree: 'DesignTree',
                       identified_stakeholders: List[str],
                       phase: str) -> 'ClosingResult':
        """
        Conducts the closing protocol after frontier is empty.
        Returns whether session is truly complete or needs re-opening.
        """
        
        new_information = []
        
        # Level 1: Self
        self_answer = self._ask(self.LEVEL_1_SELF)
        if self._is_substantive(self_answer):
            new_information.append({
                "level": "self",
                "response": self_answer,
                "extracted": self._extract_new_nodes(self_answer, design_tree)
            })
        
        # Level 2: Each identified stakeholder
        for stakeholder in identified_stakeholders:
            question = self.LEVEL_2_STAKEHOLDER_TEMPLATE.format(
                stakeholder=stakeholder
            )
            answer = self._ask(question)
            if self._is_substantive(answer):
                new_information.append({
                    "level": "stakeholder",
                    "stakeholder": stakeholder,
                    "response": answer,
                    "extracted": self._extract_new_nodes(answer, design_tree)
                })
        
        # Level 3: Situation
        situation_answer = self._ask(self.LEVEL_3_SITUATION)
        if self._is_substantive(situation_answer):
            new_information.append({
                "level": "situation",
                "response": situation_answer,
                "extracted": self._extract_new_nodes(situation_answer, design_tree)
            })
        
        # If anything new surfaced → re-open
        if new_information:
            return ClosingResult(
                session_complete=False,
                new_information=new_information,
                action="REOPEN design tree with new nodes; "
                      "may trigger additional grilling rounds",
                phase=phase
            )
        
        return ClosingResult(
            session_complete=True,
            new_information=[],
            action="Session truly complete — proceed to next phase",
            phase=phase
        )
    
    def _is_substantive(self, answer: str) -> bool:
        """Check if answer contains new information (not just 'no')"""
        non_substantive = {"no", "nope", "nothing", "not really", "n/a", 
                          "i don't think so", "can't think of anything"}
        return answer.strip().lower() not in non_substantive and len(answer.strip()) > 10
```

class EmergentOrchestratorV33:
    """
    Full orchestrator with all v3.3 systems.
    """
    
    def __init__(self, llm_client, storage, user_profile):
        self.llm = llm_client
        self.storage = storage
        self.profile = user_profile

        self.translator = NaturalLanguageTranslator(user_profile, [])
        self.devils_advocate = DevilsAdvocateProtocol(user_profile, [])
        self.assumption_eliminator = AssumptionEliminationProtocol()
        self.framework_library = ValidatedFrameworkLibrary()
        self.claim_classifier = ClaimClassifier(self.framework_library)
        self.ev_enforcer = ExpectedValueEnforcement()
        self.base_rates = BaseRateDatabase()
        self.system_bias_detector = SystemBiasDetector()
        self.closing_protocol = SessionClosingProtocol()
    
    def run_decision(self, initial_context):
        # Phase 1 + Closing
        phase1 = self._run_phase1(initial_context)
        
        # Phase 1.5 + Closing (leverage with full validation)
        leverage_map = self._run_phase15(phase1)
        
        # Phase 2 + Closing
        phase2 = self._run_phase2(leverage_map)
        
        if phase2.get("pareto_analysis", {}).get("win_win_possible"):
            return self._format_win_win(phase2, leverage_map)
        
        # Phase 3 + Closing
        phase3 = self._run_phase3(leverage_map)
        
        # Solver with calculation-gated leverage
        solver = LeverageModifiedMinimaxSolver(
            self.profile, leverage_map, self.translator.translation_log
        )
        recommendation = solver.solve(phase3)
        
        # Store with complete audit
        self._store_with_full_audit(...)
        
        return recommendation
