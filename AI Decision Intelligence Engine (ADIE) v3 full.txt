## 1. Executive Summary

### 1.1 Project Vision

The AI Decision Intelligence Engine (ADIE) is a deterministic, structured decision-making system that combines:
- **Game Theory** (Pareto efficiency/win-win analysis)
- **Risk Minimization** (Minimax decision rule)
- **Leverage Mapping** (Exhaustive power analysis including hidden leverage)
- **Baseline Context Analysis** (Status quo comparison)

**Core Philosophy:** The system uses LLMs as interview facilitators and parsers, NOT as decision-makers. All core logic is programmatic, deterministic, and mathematically grounded.

### 1.2 The v3.1 Innovation: Leverage Mapping

**The Problem:** Users make decisions based on their *perceived* leverage, not their *actual* leverage. When perception ≠ reality, decisions fail:
- Users with hidden leverage under-negotiate
- Users without leverage over-commit

**The Solution:** Phase 1.5 performs an exhaustive mapping of ALL leverage—including leverage users don't know they have—through:
1. **Emergent grilling** using the six-domain taxonomy as a strategic guide
2. **Deterministic pattern detection** based on cognitive bias research
3. **Emergent discovery** leveraging LLM ideation
4. **Hybrid validation** ensuring research-grounded discoveries

### 1.3 How Leverage Mapping Changes Everything

| Component | Without Leverage Map | With Leverage Map |
|-----------|---------------------|-------------------|
| **Worst-case utility** | Based on user's beliefs | Based on actual leverage |
| **Pareto search** | Limited by perceived leverage | Expanded by actual leverage |
| **Red line enforceability** | Assumed true | Validated against leverage |
| **BATNA calculation** | User-stated alternatives | All actual alternatives |
| **Confidence** | Based on incomplete picture | Based on actual power |

### 1.4 Key Differentiators

| Feature | Traditional AI Advice | ADIE |
|---------|----------------------|------|
| Decision Logic | LLM discretion | Deterministic algorithms |
| Interview Method | Generic chat | Emergent grilling protocol |
| Leverage Analysis | None | Exhaustive mapping including hidden leverage |
| Risk Analysis | Qualitative | Quantitative Minimax |
| Win-Win Detection | Ad hoc | Formal Pareto analysis |
| Context Grounding | Session-only | Persistent user profile + QMD retrieval |
| Bias Prevention | None | Facts vs. decisions separation + user confirmation |

### 1.5 Design Principles

1. **Emergent Questioning:** Questions generated from design tree frontier, never predetermined
2. **Facts vs. Decisions:** LLM answers facts from context; user answers decisions
3. **Determinism First:** LLM discretion minimized; every calculation uses programmatic algorithms
4. **Leverage-Aware:** All calculations adjusted by discovered leverage
5. **Hidden Leverage Detection:** Actively hunt for leverage users don't know they have
6. **Never Assume:** LLM must ask user rather than guess (Epistemic Halt)
7. **Persistent Context:** User profiles and decision history stored in local, searchable system
8. **Explainability:** Every recommendation traceable through audit trail

### 2.2 Core Theoretical Frameworks

#### 2.2.1 Game Theory — Pareto Efficiency (Win-Win)
- **Source:** Vilfredo Pareto, multi-objective optimization
- **Application:** Detect choices where all stakeholders benefit or are no worse off
- **Mathematical Definition:** A state is Pareto-optimal if no individual can be made better off without making someone else worse off
- **v3.1 Enhancement:** Leverage map expands the Pareto search space

#### 2.2.2 Risk Minimization — Minimax Decision Rule
- **Source:** John von Neumann, 1928
- **Application:** Choose action that minimizes maximum possible loss
- **Mathematical Definition:**
  ```
  v_i = max_{a_i} min_{a_{-i}} v_i(a_i, a_{-i})
  ```
  Where:
  - `a_i` = action taken by user
  - `a_{-i}` = actions of other stakeholders/chance
  - `v_i` = utility function
- **v3.1 Enhancement:** Leverage multipliers adjust utility calculations; BATNA provides floor protection

#### 2.2.3 Leverage Mapping (NEW in v3.1)
- **Sources:** Fisher & Ury (1981), Emerson (1962), Cialdini (2009), Kahneman & Tversky (1979), Burt (1992), Akerlof (1970)
- **Application:** Exhaustive mapping of all leverage including hidden leverage
- **Integration:** Modifies all downstream calculations

#### 2.2.4 Status Quo — Baseline Context
- **Concept:** User's current state as reference point
- **Application:** No recommendation if worst-case scenario is worse than baseline
- **Implementation:** All utility normalized to baseline (0.0)
- **v3.1 Enhancement:** Leverage improves baseline position assessment

### 2.3 LLM Role Boundaries

## 3. Core Mathematical Foundations

### 3.1 Utility Function System

#### 3.1.1 Normalized Scale
All utility values use signed unit interval: `[-1.0, +1.0]`

```
+1.0  ─── Maximum possible gain (user's "ceiling")
 0.0  ─── No change from baseline (status quo)
-1.0  ─── Catastrophic loss (user's red line)
```

#### 3.1.2 Dimension Templates

```python
# ============================================
# UTILITY DIMENSION FORMULAS
# ============================================

def financial_utility(new_income, baseline_income, red_line_income, ceiling_income):
    """
    Maps financial change to [-1.0, +1.0]
    
    -1.0 = at or below red_line_income
     0.0 = exactly baseline_income
    +1.0 = at or above ceiling_income
    """
    if new_income <= red_line_income:
        return -1.0
    elif new_income >= ceiling_income:
        return +1.0
    elif new_income == baseline_income:
        return 0.0
    elif new_income < baseline_income:
        # Loss: interpolate from baseline (0) to red_line (-1)
        ratio = (baseline_income - new_income) / (baseline_income - red_line_income)
        return -1.0 * ratio
    else:
        # Gain: interpolate from baseline (0) to ceiling (+1)
        ratio = (new_income - baseline_income) / (ceiling_income - baseline_income)
        return +1.0 * ratio


def emotional_utility(new_state_score, baseline_score, scale_range=10):
    """
    Maps emotional well-being to [-1.0, +1.0]
    User rates states on 0-10 scale
    """
    delta = new_state_score - baseline_score
    return delta / (scale_range / 2)


def temporal_utility(hours_gained_or_lost, total_free_hours):
    """
    Maps time freedom change to [-1.0, +1.0]
    """
    return hours_gained_or_lost / (total_free_hours / 2)


def reputational_utility(new_reputation_score, baseline_score, scale_range=10):
    """
    Maps social/professional standing to [-1.0, +1.0]
    """
    delta = new_reputation_score - baseline_score
    return delta / (scale_range / 2)
```

#### 3.1.3 Weighting System (AHP — Analytic Hierarchy Process)

```python
# ============================================
# WEIGHT DERIVATION VIA PAIRWISE COMPARISON
# ============================================

def derive_weights(pairwise_matrix):
    """
    Input: NxN matrix where user compared each dimension against others
    Output: normalized weights summing to 1.0
    
    User answers: "Which matters more? Rate 1-9"
    (1 = equal, 3 = moderately more, 9 = extremely more)
    """
    import numpy as np
    
    # Calculate eigenvector of the pairwise matrix
    eigenvalues, eigenvectors = np.linalg.eig(pairwise_matrix)
    max_eigenvalue_index = np.argmax(eigenvalues.real)
    principal_eigenvector = np.real(eigenvectors[:, max_eigenvalue_index])
    
    # Normalize to sum to 1.0
    weights = principal_eigenvector / np.sum(principal_eigenvector)
    
    # Calculate consistency ratio
    consistency_ratio = calculate_consistency_ratio(pairwise_matrix, max_eigenvalue_index)
    
    if consistency_ratio > 0.1:
        raise ValueError("Inconsistent preferences detected. Re-interview required.")
    
    return weights
```

#### 3.1.4 Nonlinearity with Thresholds

```python
# ============================================
# NONLINEAR UTILITY WITH THRESHOLDS
# ============================================

def utility_with_thresholds(value, thresholds):
    """
    Piecewise linear interpolation between threshold points
    
    Example thresholds for savings:
    [
        {"value": 1, "utility": -0.8},   # Below 1 month → severe penalty
        {"value": 3, "utility": -0.4},   # Below 3 months → moderate penalty  
        {"value": 6, "utility": 0.0},    # 6 months → baseline
        {"value": 12, "utility": 0.6},   # 12 months → significant gain
        {"value": 24, "utility": 1.0},   # 24 months → maximum gain
    ]
    """
    thresholds = sorted(thresholds, key=lambda t: t["value"])
    
    if value <= thresholds[0]["value"]:
        return thresholds[0]["utility"]
    if value >= thresholds[-1]["value"]:
        return thresholds[-1]["utility"]
    
    for i in range(len(thresholds) - 1):
        lower = thresholds[i]
        upper = thresholds[i + 1]
        
        if lower["value"] <= value <= upper["value"]:
            ratio = (value - lower["value"]) / (upper["value"] - lower["value"])
            return lower["utility"] + ratio * (upper["utility"] - lower["utility"])
```

### 3.2 Leverage Mathematics (NEW in v3.1)

#### 3.2.1 Leverage Strength Calculation

Based on Fishbein & Ajzen (1975) expectancy-value model and multidimensional scaling:

```python
def calculate_leverage_strength(
    base_power: float,          # 1.0-5.0 raw power assessment
    durability_factor: float,   # 0.5-1.5 (Williamson, 1985)
    transferability_factor: float,  # 0.5-1.5 (Coleman, 1988)
    enforceability_factor: float    # 0.0-1.0 (North, 1990)
) -> float:
    """
    Research Basis:
    - Fishbein & Ajzen (1975) - Expectancy-value model
    - Kruskal & Wish (1978) - Multidimensional scaling
    - Williamson (1985) - Transaction cost economics
    - Coleman (1988) - Social capital theory
    - North (1990) - Institutional economics
    """
    adjusted_power = base_power * durability_factor * transferability_factor
    return adjusted_power * enforceability_factor
```

#### 3.2.2 Leverage Multiplier Formula

Based on French & Raven (1959) bases of power:

```python
def leverage_multiplier(
    leverage_strength: float,   # 1-5
    applicability: float,       # 0-1 (how relevant to this choice)
    enforceability: float,      # 0-1 (can actually be used?)
    awareness_gap: float        # 0-1 (hidden vs. known leverage)
) -> float:
    """
    Research Basis:
    - French & Raven (1959) - Bases of power
    - Raven (1965) - Social influence and power
    - Falbo & Peplau (1980) - Power strategies
    - Mussweiler & Strack (1999) - Hypothesis-testing
    """
    # Base multiplier from strength
    base_multiplier = 1 + (leverage_strength - 3) * 0.2
    
    # Apply applicability discount
    applicable_multiplier = base_multiplier * applicability
    
    # Apply enforceability discount
    enforceable_multiplier = applicable_multiplier * enforceability
    
    # Hidden leverage bonus (discovery value)
    hidden_bonus = 1 + (awareness_gap * 0.15)
    
    return enforceable_multiplier * hidden_bonus
```

#### 3.2.3 Leverage-Adjusted Utility Calculation

Based on Keeney & Raiffa (1976) multi-attribute utility theory:

```python
def calculate_leverage_adjusted_utility(
    base_utility: float,
    leverage_map: 'LeverageMap',
    choice_id: str
) -> float:
    """
    Research Basis:
    - Keeney & Raiffa (1976) - Decisions with Multiple Objectives
    - Dyer (2005) - MAUT
    - Raiffa (1982) - The Art and Science of Negotiation
    """
    total_adjustment = 0.0
    
    for leverage in leverage_map.get_applicable_leverage(choice_id):
        if leverage.domain == "structural":
            # BATNA directly improves worst-case
            # Based on Raiffa (1982)
            adjustment = leverage.strength * 0.1 * leverage.enforceability
            total_adjustment += adjustment
            
        elif leverage.domain == "negotiation":
            # Negotiation leverage improves likely-case
            # Based on Thompson (1990)
            adjustment = leverage.strength * 0.08 * leverage.transferability
            total_adjustment += adjustment
            
        elif leverage.domain == "informational":
            # Information asymmetry reduces uncertainty premium
            # Based on Akerlof (1970), Stiglitz (2002)
            adjustment = leverage.strength * 0.06 * leverage.user_awareness
            total_adjustment += adjustment
    
    # Apply loss aversion adjustment
    # Based on Kahneman & Tversky (1979)
    if base_utility < 0:
        total_adjustment *= 2.25  # Loss aversion coefficient
    
    return base_utility + total_adjustment
```

#### 3.2.4 BATNA Floor Protection

Based on Ben-Haim (2006) info-gap decision theory:

```python
def batna_floor_protection(
    leverage_point: 'LeveragePoint',
    current_worst_case: float
) -> float:
    """
    BATNA provides a guaranteed minimum outcome.
    Research Basis:
    - Ben-Haim (2006) - Info-Gap Decision Theory
    - Fisher & Ury (1981) - BATNA concept
    """
    if leverage_point.domain == "structural" and leverage_point.batna:
        # BATNA floor: can't be worse than walking away
        batna_floor = -leverage_point.strength * 0.15
        return max(current_worst_case, batna_floor)
    
    return current_worst_case
```

### 3.3 Minimax Calculation

#### 3.3.1 Core Algorithm (Standard)

```python
class MinimaxSolver:
    def solve(self, phase3_output: Dict) -> Dict:
        """
        Implements: v_i = max_{a_i} min_{a_{-i}} v_i(a_i, a_{-i})
        
        For each choice:
        1. Find worst-case branch (minimum utility)
        2. Select choice with highest worst-case utility
        """
        choices = phase3_output["choices"]
        evaluations = []
        
        for choice in choices:
            evaluation = self._evaluate_choice(choice)
            evaluations.append(evaluation)
        
        # Apply minimax selection
        best = self._minimax_select(evaluations)
        
        return {
            "analysis": evaluations,
            "recommendation": best,
            "confidence": self._calculate_confidence(best, evaluations),
            "worst_case_comparison": self._compare_to_baseline(best)
        }
```

#### 3.3.2 Red Line Enforcement

```python
def _check_red_lines(self, branch: Dict) -> bool:
    """
    Any red line violation = automatic -1.0 utility
    No trade-off possible
    """
    for red_line in self.red_lines:
        if red_line in branch.get("red_line_risks", []):
            return True
    return False
```

#### 3.3.3 Reversibility Bonus

```python
def _minimax_select(self, evaluations: List[Dict]) -> Dict:
    """
    Reversible choices get +0.1 bonus to worst-case score
    Rationale: Can always fall back to another option
    """
    for eval in evaluations:
        eval["adjusted_worst_case"] = (
            eval["worst_case_utility"] + eval["reversibility_bonus"]
        )
    
    best = max(evaluations, key=lambda e: e["adjusted_worst_case"])
    
    return {
        "selected_choice": best["choice_id"],
        "selection_rationale": (
            f"Worst-case utility: {best['worst_case_utility']:.2f} "
            f"(+{best['reversibility_bonus']:.1f} reversibility bonus)"
        ),
        "all_worst_cases": [...]
    }
```

## 4. The Emergent Grilling Protocol

### 4.1 What It Does

The grilling engine is the **primitive** that powers all interview phases. Based on Matt Pocock's grilling skill:

> "It maps the subject as a **design tree**: every decision branches into the decisions that hang off it, and interviews you branch by branch until nothing is left silently assumed."

The engine:

1. Maps the subject as a **design tree**
2. Calculates the **frontier** (decisions whose prerequisites are settled)
3. Generates questions for the **entire frontier** in one round
4. Updates the tree based on answers
5. Recalculates the frontier
6. Repeats until the frontier is empty

### 4.2 The Three Core Concepts

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  DESIGN TREE                                                │
│  The model of the subject: decisions with decisions          │
│  hanging off them                                           │
│                                                             │
│         ┌──────────────┐                                   │
│         │  Decision A  │ ← Settled                         │
│         └──────┬───────┘                                   │
│                │                                            │
│         ┌──────┴───────┐                                   │
│         │  Decision B  │ ← Settled (prerequisite: A)       │
│         └──────┬───────┘                                   │
│                │                                            │
│         ┌──────┴───────┐     ┌──────────────┐             │
│         │  Decision C  │     │  Decision D  │ ← FRONTIER  │
│         │  (depends on │     │  (prerequisite:│   (can be  │
│         │   unsettled) │     │   B settled)   │  asked now)│
│         └──────────────┘     └──────────────┘             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 The Round Structure

> "Two questions never share a round if one depends on the other; a question that hinges on an answer still open belongs to a later round."

**Format:**
```
❓ 1: [Question Title]
[Question body specific to this decision context]
➡️ Recommended: [Agent's best inference from available context]

❓ 2: [Question Title]
[Question body specific to this decision context]
➡️ Recommended: [Agent's best inference from available context]

[... more frontier questions ...]
```

**Answer format:**
```
1: [answer to question 1]
2: [answer to question 2]
3: no, [explanation]
```

### 4.4 Facts vs. Decisions

> "Facts are the skill's own job: when a frontier question needs something the environment can settle, it dispatches a sub-agent to go and find out rather than asking you. It does not block on that; only the questions downstream of a running exploration wait. Decisions are yours, and it must wait for them."

| Type | Who Answers | How |
|------|-------------|-----|
| **Fact** | LLM (from context/framework) | LLM looks up, doesn't ask user |
| **Decision** | User (Epistemic Halt) | LLM must wait for user answer |

### 4.5 Termination Conditions

The session ends when:
1. **Frontier is empty**: no more unsettled decisions whose prerequisites are met
2. **User confirms**: shared understanding reached
3. **Escalation**: scope too large for one session (switch to wayfinder)

### 4.6 Open-Ended Design

**Critical requirement from grill-me:**

> "It asks in **rounds**: each round is the whole **frontier** (every question whose prerequisites you have already settled), so you are never asked something that hinges on an answer it hasn't heard yet."

> "How many questions should I expect, and how do I know when it ends?
> Count rounds, not questions. Forty-six questions across four rounds is an ordinary session. It ends when the frontier is empty: every branch visited, nothing left silently assumed."

**Implications for ADIE:**
- No fixed number of questions
- No fixed number of rounds
- No predetermined topics or themes
- Questions emerge from the specific decision context
- Session length scales with decision complexity

### 4.7 The Master System Prompt

```

You are the Grilling Agent in a Deterministic Decision Engine.
You conduct structured interviews using the grilling protocol.

# THE PROTOCOL

You model the subject as a design tree: every decision branches into

is left silently assumed.

## Frontier Calculation
Each round, you:
1. Identify all decisions whose prerequisites are settled
2. Generate questions for ALL of them (the frontier)
3. Never ask a question that depends on an unsettled question

## Question Format
Every question arrives in this exact shape:
❓ [number]: [Title]
[Question body specific to this decision context]
➡️ Recommended: [Your best answer based on available context]

  and provide your best recommendation with low confidence.

- Recalculate the frontier

1. Frontier is empty (all decisions settled)
2. User confirms shared understanding
3. Scope too large (escalate to multi-session)

  "vNM utility construction", "Minimax regret principle")
- USER_INPUT: Obtained via Epistemic Halt

If you cannot cite one of these three, you are speculating.
Speculation triggers an EPISTEMIC HALT.

When a frontier question cannot be answered via CONTEXT or FRAMEWORK:
<<<HALT>>>

ROUND: [N]
BLOCKING_NODE: [the question]
WHY_BLOCKED: [why neither CONTEXT nor FRAMEWORK resolves this]
```

### 4.8 Design Tree Data Structure (Complete Implementation)

```python
from dataclasses import dataclass, field
from typing import List, Optional, Dict
from enum import Enum

class NodeType(Enum):
    SITUATION = "situation"
    STAKEHOLDER = "stakeholder"
    CHOICE = "choice"
    OUTCOME = "outcome"
    UTILITY = "utility"
    ASSUMPTION = "assumption"
    LEVERAGE_DOMAIN = "leverage_domain"
    LEVERAGE_POINT = "leverage_point"
    OTHER = "other"

@dataclass
class DecisionNode:
    id: str
    description: str
    node_type: NodeType
    
    # Tree structure
    prerequisites: List['DecisionNode'] = field(default_factory=list)
    dependents: List['DecisionNode'] = field(default_factory=list)
    
    # State
    is_settled: bool = False
    answer: Optional[str] = None
    answer_source: Optional[str] = None  # "llm_fact" | "user" | "framework"
    answer_basis: Optional[str] = None
    
    # For stateful mode
    is_term: bool = False  # Should be written to CONTEXT.md
    is_adr: bool = False   # Should be written as ADR

class DesignTree:
    def __init__(self):
        self.nodes: Dict[str, DecisionNode] = {}
        self.root_nodes: List[DecisionNode] = []
    
    def add_node(
        self, 
        node_id: str,
        description: str,
        node_type: NodeType,
        prerequisites: List[str] = None
    ) -> DecisionNode:
        """Add a node with optional prerequisites"""
        
        node = DecisionNode(
            id=node_id,
            description=description,
            node_type=node_type
        )
        
        if prerequisites:
            for prereq_id in prerequisites:
                prereq = self.nodes.get(prereq_id)
                if prereq:
                    node.prerequisites.append(prereq)
                    prereq.dependents.append(node)
        
        self.nodes[node_id] = node
        if not prerequisites:
            self.root_nodes.append(node)
        
        return node
    
    def settle_node(self, node_id: str, answer: str, source: str, basis: str):
        """Settle a node with an answer"""
        
        node = self.nodes[node_id]
        node.is_settled = True
        node.answer = answer
        node.answer_source = source
        node.answer_basis = basis
    
    def get_frontier(self) -> List[DecisionNode]:
        """Calculate frontier: unsettled nodes whose prerequisites are settled"""
        
        frontier = []
        for node in self.nodes.values():
            if not node.is_settled:
                if all(p.is_settled for p in node.prerequisites):
                    frontier.append(node)
        return frontier
    
    def to_visualization(self) -> str:
        """Generate text visualization of the tree"""
        
        output = []
        
        def render_node(node, depth=0):
            status = "✅" if node.is_settled else "⏳"
            prefix = "  " * depth
            output.append(f"{prefix}{status} {node.description}")
            
            if node.is_settled:
                output.append(f"{prefix}   Answer: {node.answer}")
                output.append(f"{prefix}   Source: {node.answer_source}")
            
            for dep in node.dependents:
                render_node(dep, depth + 1)
        
        for root in self.root_nodes:
            render_node(root)
        
        return "\n".join(output)
```

### 5.3 The Emergent Engine Core (Complete Implementation)

```python
class EmergentGrillingEngine:
    """
    Implements the true grilling protocol where questions emerge
    from the design tree frontier, not from predetermined lists.
    
    Based on Matt Pocock's grilling skill.
    """
    
    def __init__(self, llm_client, objective: str, mode: str = "grill-me"):
        self.llm = llm_client
        self.objective = objective  # What this session must achieve
        self.mode = mode  # grill-me | grill-with-docs | wayfinder
        
        # Design tree - the core data structure
        self.design_tree = DesignTree()
        
        # Session state
        self.round_number = 0
        self.asked_questions: List[Question] = []
        self.user_answers: List[Answer] = []
        self.facts_resolved: List[Fact] = []
        
        # For stateful mode
        self.context_md = ContextMD() if mode == "grill-with-docs" else None
        self.adr_store = ADRStore() if mode == "grill-with-docs" else None
    
    def run_session(self, initial_context: dict) -> dict:
        """
        Runs the grilling session until frontier is empty.
        The number of rounds is EMERGENT.
        """
        
        # Step 1: Initialize design tree from context
        self._initialize_tree(initial_context)
        
        # Step 2: Loop until frontier is empty
        while True:
            # Calculate current frontier
            frontier = self._calculate_frontier()
            
            # Check termination
            if not frontier:
                # All decisions settled
                return self._compile_output()
            
            # Generate questions for frontier
            questions = self._generate_frontier_questions(frontier)
            
            # Conduct round (handles facts vs decisions)
            round_result = self._conduct_round(questions)
            
            # Update tree with answers
            self._update_tree(round_result)
            
            # Increment round
            self.round_number += 1
    
    def _calculate_frontier(self) -> List[DecisionNode]:
        """
        The frontier is: every decision whose prerequisites are settled.
        This is the core innovation of the grilling protocol.
        """
        return self.design_tree.get_frontier()
    
    def _generate_frontier_questions(
        self, 
        frontier: List[DecisionNode]
    ) -> List[Question]:
        """
        LLM generates questions for the current frontier.
        Questions are SPECIFIC to this decision context.
        """
        
        prompt = f"""
        You are conducting a grilling session for: {self.objective}
        
        CURRENT DESIGN TREE:
        {self.design_tree.to_visualization()}
        
        CURRENT FRONTIER (ask about ALL of these):
        {[f"- {node.description}" for node in frontier]}
        
        PREVIOUS ANSWERS:
        {self._format_previous_answers()}
        
        GENERATE QUESTIONS:
        - One question per frontier node
        - Questions must be SPECIFIC to this decision context
        - Use information from previous answers to make questions precise
        - If you can answer a node yourself (it's a FACT), provide your
          answer with basis
        - If a node requires user input (it's a DECISION), mark as
          USER_INPUT_REQUIRED
        
        FORMAT:
        ❓ [number]: [Title specific to this decision]
        [Question body using context-specific language]
        ➡️ Recommended: [Your answer OR "USER_INPUT_REQUIRED" + why]
        """
        
        response = self.llm.generate(prompt)
        return self._parse_questions(response)
    
    def _conduct_round(self, questions: List[Question]) -> List[Answer]:
        """
        Handles one round: LLM answers facts, user answers decisions.
        """
        
        answers = []
        user_questions = []
        
        # Separate facts from decisions
        for q in questions:
            if q.recommendation != "USER_INPUT_REQUIRED":
                # LLM can answer this (fact)
                answers.append(Answer(
                    question=q,
                    answer=q.recommendation,
                    source="llm_fact",
                    basis=q.basis
                ))
            else:
                # User must answer this (decision)
                user_questions.append(q)
        
        # If there are user questions, ask them all at once
        if user_questions:
            user_responses = self._ask_user_batch(user_questions)
            for q, resp in zip(user_questions, user_responses):
                answers.append(Answer(
                    question=q,
                    answer=resp,
                    source="user"
                ))
        
        return answers
    
    def _ask_user_batch(self, questions: List[Question]) -> List[str]:
        """
        Presents all user questions in one round.
        User can answer by number: "1: yes, 2: second option, 3: no because..."
        """
        
        # Format for user
        output = "\n🛑 USER INPUT REQUIRED\n\n"
        
        for i, q in enumerate(questions, 1):
            output += f"❓ {i}: {q.title}\n"
            output += f"{q.body}\n"
            output += f"➡️ Recommended: {q.recommendation}\n\n"
        
        output += "Please answer by number (e.g., '1: yes', '2: option B'):\n"
        
        # Get user input (in real implementation, this would be async)
        user_input = input(output)
        
        # Parse numbered responses
        return self._parse_numbered_answers(user_input, questions)
    
    def _initialize_tree(self, context: dict):
        """Initialize design tree from context - implementation varies by phase"""
        pass
    
    def _compile_output(self) -> dict:
        """Compile final output from settled tree"""
        pass
    
    def _format_previous_answers(self) -> str:
        """Format previous answers for prompt context"""
        pass
    
    def _parse_questions(self, response: str) -> List[Question]:
        """Parse LLM response into Question objects"""
        pass
```

```python
class LeverageIntegrationManager:
    """
    Manages the flow of leverage information between phases.
    Ensures the LeverageMap is available to all downstream calculations.
    """
    
    def __init__(self, leverage_map: 'LeverageMap'):
        self.leverage_map = leverage_map
    
    def enhance_phase2_pareto_search(self, context: dict) -> dict:
        """Expands Pareto search space based on discovered leverage"""
        context["leverage_multiplier"] = self._calculate_negotiation_leverage()
        context["pareto_expansion"] = self._identify_leverage_enabled_options()
        return context
    
    def adjust_phase3_utility(self, choice_id: str, base_utility: float) -> float:
        """Applies leverage multipliers to utility calculations"""
        return calculate_leverage_adjusted_utility(
            base_utility, self.leverage_map, choice_id
        )
    
    def modify_minimax_worst_case(
        self, choice_id: str, worst_case: float
    ) -> float:
        """Applies BATNA floor protection and leverage improvements"""
        # BATNA floor
        for leverage in self.leverage_map.get_applicable_leverage(choice_id):
            worst_case = batna_floor_protection(leverage, worst_case)
        
        # Resource leverage recovery bonus
        for leverage in self.leverage_map.get_applicable_leverage(choice_id):
            if leverage.domain == "resource":
                recovery_bonus = leverage.strength * 0.1
                worst_case += recovery_bonus * 0.3
        
        return worst_case
    
    def validate_red_line_enforceability(
        self, red_line: str
    ) -> 'RedLineValidation':
        """Checks if user's red lines are actually enforceable given leverage"""
        enforcement_leverage = self.leverage_map.get_enforcement_leverage()
        return RedLineValidation(
            red_line=red_line,
            enforceable=enforcement_leverage.total_strength >= 3.0,
            enforcement_mechanisms=enforcement_leverage.get_mechanisms(),
            confidence=enforcement_leverage.total_strength / 5.0
```

```
- The specific decision context

## The Protocol
Follow the standard emergent grilling protocol:
- Model as design tree (using domains as initial branches)
- Calculate frontier each round
- Generate questions for frontier
- Facts you answer yourself; decisions ask the user
- Continue until frontier is empty

## Critical Distinctions
FACTS about leverage (e.g., "you have 4 months runway")
→ LLM can identify from context

USER'S BELIEF about leverage (e.g., "I feel I have no options")
→ Must ask user

DISCREPANCY between belief and reality
→ This is the hidden leverage! Flag it explicitly.

## Hidden Leverage Detection
As you conduct the interview, actively look for:
1. Undervalued BATNA (user claims no alternatives but has them)
2. Unrecognized scarcity (user is unique but doesn't realize)
3. Time asymmetry blindness (user can wait but thinks they can't)
4. Dependency misreading (counterparty depends on user more than user thinks)
5. Information asymmetry unawareness (user knows valuable things)
6. Network position blindness (user occupies structural hole)

When you detect a potential hidden leverage:
- Note it explicitly in your output
- Ask follow-up questions to validate
- Assess its strength and exercisability

## Leverage Strength Assessment
For each leverage point discovered, assess:
- Strength (1-5 scale)
- Durability (permanent | long-term | situational | ephemeral)
- Transferability (can be used elsewhere?)
- Enforceability (can actually be exercised?)
- Awareness (does user know? does counterparty know?)

## Output Requirements

1. Complete leverage map (all discovered leverage points)
2. Hidden leverage discoveries (user-unaware leverage)
3. Leverage strength assessments (1-5 scale)
4. Leverage dynamics (increasing/decreasing)
```

```python
@dataclass
class LeverageMap:
    """Complete output of Phase 1.5"""
    
    decision_id: str
    timestamp: datetime
    
    # All discovered leverage points
    leverage_points: List['LeveragePoint']
    
    # Hidden leverage (user was unaware)
    hidden_leverage: List['HiddenLeverageDiscovery']
    
    # Leverage by domain
    domain_summary: Dict[str, 'DomainSummary']
    
    # Stakeholder leverage comparison
    stakeholder_leverage: Dict[str, 'StakeholderLeverage']
    
    # Leverage dynamics
    leverage_trajectory: 'LeverageTrajectory'
    
    # Strategic implications
    strategic_recommendations: List[str]
    
    # Validation metadata
    validation_metadata: 'ValidationMetadata'
    
    # Methods
    def get_applicable_leverage(self, choice_id: str) -> List['LeveragePoint']:
        """Get all leverage points applicable to a specific choice"""
        return [
            lp for lp in self.leverage_points
            if choice_id in lp.applies_to_choices
        ]
    
    def get_domain_leverage(self, domain: str) -> 'DomainSummary':
        """Get leverage summary for a specific domain"""
        return self.domain_summary[domain]
    
    def get_leverage_by_type(self, leverage_type: str) -> Optional['LeveragePoint']:
        """Get leverage point by specific type"""
        for lp in self.leverage_points:
            if lp.type == leverage_type:
                return lp
        return None
    
    def get_enforcement_leverage(self) -> 'EnforcementLeverage':
        """Get all leverage that can enforce red lines"""
        enforcement = [
            lp for lp in self.leverage_points
            if lp.enforceable and lp.strength >= 3.0
        ]
        return EnforcementLeverage(
            leverage_points=enforcement,
            total_strength=sum(lp.strength for lp in enforcement) / max(len(enforcement), 1)
        )


@dataclass
class LeveragePoint:
    """Individual leverage point"""
    
    id: str
    domain: str  # structural, negotiation, psychological, resource, informational, positional
    type: str    # Specific type within domain
    description: str
    
    # Strength assessment (1-5)
    strength: float
    strength_basis: str  # Research framework or calculation used
    
    # Awareness
    user_aware: bool
    counterparty_aware: bool
    
    # Properties
    durability: str    # permanent | long-term | situational | ephemeral
    transferable: bool
    enforceable: bool
    batna: bool = False  # Is this a BATNA-type leverage?
    
    # Applicability
    applies_to_stakeholders: List[str]
    applies_to_choices: List[str]
    
    # Impact metrics
    utility_multiplier: float
    worst_case_improvement: float
    
    # Validation
    confidence: float  # 0-1
    research_basis: str
    evidence: Dict[str, Any]
```

```python
class LeverageEnhancedParetoAnalyzer:
    """
    Pareto analyzer that uses leverage map to expand search space
    and identify win-win solutions the user didn't know were possible.
    """
    
    def __init__(self, leverage_map: 'LeverageMap'):
        self.leverage_map = leverage_map
    
    def find_pareto_improvements(
        self, context: dict, stakeholders: List[str]
    ) -> List['ParetoImprovement']:
        """
        Searches for Pareto improvements using leverage-expanded options.
        """
        
        # Standard options (from user's stated choices)
        standard_options = self._get_stated_choices(context)
        
        # Leverage-enabled options (new possibilities due to leverage)
        leverage_options = self._generate_leverage_enabled_options(
            standard_options, self.leverage_map
        )
        
        # All options to evaluate
        all_options = standard_options + leverage_options
        
        # Evaluate each for Pareto efficiency
        pareto_improvements = []
        for option in all_options:
            evaluation = self._evaluate_pareto_efficiency(option, stakeholders)
            if evaluation.is_pareto_improvement:
                pareto_improvements.append(evaluation)
        
        return pareto_improvements
    
    def _generate_leverage_enabled_options(
        self, standard_options: List[dict], leverage_map: 'LeverageMap'
    ) -> List[dict]:
        """
        Generates new option possibilities enabled by discovered leverage.
        These are options the user didn't consider because they
        didn't know they had the leverage.
        """
        new_options = []
        
        # Structural leverage enables new negotiation positions
        structural = leverage_map.get_domain_leverage("structural")
        if structural.total_strength >= 3.5:
            new_options.append({
                "type": "aggressive_negotiation",
                "description": "Counter at higher price given strong BATNA",
                "enabled_by": [lp.id for lp in structural.leverage_points],
                "feasible": True
            })
        
        # Informational leverage enables strategic timing
        informational = leverage_map.get_domain_leverage("informational")
        if informational.total_strength >= 4.0:
            new_options.append({
                "type": "strategic_delay",
                "description": "Wait for counterparty's deadline pressure to build",
                "enabled_by": [lp.id for lp in informational.leverage_points],
                "feasible": True
            })
        
        # Time asymmetry enables patient negotiation
        time_leverage = leverage_map.get_leverage_by_type("time_asymmetry")

            new_options.append({
                "type": "patient_negotiation",
                "description": "Multiple rounds over weeks, let them come to you",
                "enabled_by": [time_leverage.id],
                "feasible": True
            })
```

### 8.5 Example: Emergent Game Theory Analysis

**Context**: Client offers $50k, user wants $70k

**Round 1** (frontier: stakeholder utilities):
```
❓ 1: Client's Utility Dimensions
What does the client value beyond price? Timeline? Quality? Risk
reduction? Future relationship?
➡️ Recommended: Based on negotiation theory (Harvard Negotiation
Project), clients typically value: on-time delivery, quality
assurance, communication, and risk mitigation. FRAMEWORK: Fisher &
Ury's "Getting to Yes" - interests vs. positions.

❓ 2: User's Utility Dimensions
Beyond the $20k difference, what do you value? Payment terms? Creative
control? Portfolio value? Future referrals?
➡️ Recommended: USER_INPUT_REQUIRED - Personal priorities vary.
Common freelancer interests: cash flow (early payment), creative
freedom, portfolio building, relationship capital.

❓ 3: ZOPA Existence
Is there a Zone of Possible Agreement? What is each party's:
- Reservation point (minimum acceptable)
- Aspiration point (ideal outcome)
➡️ Recommended: USER_INPUT_REQUIRED - Need to know your minimum and
their maximum to determine if a deal is possible at all.
```

**Round 2** (frontier: after utilities mapped):
```
❓ 4: Pareto Improvement Search
Given client values [timeline, quality, risk reduction] and you value
[cash flow, portfolio, future work], can we construct a deal that
improves both parties?

Options to explore:
A) $55k with 50% upfront (improves your cash flow, reduces their risk)
B) $50k + performance bonus for early delivery (aligns incentives)
C) $60k with extended timeline (they get lower risk, you get higher pay)
D) $50k + case study rights + referral commitment (future value)

➡️ Recommended: Option B likely creates Pareto improvement: client
gets faster delivery (their interest), you get performance upside
(your interest). FRAMEWORK: Nash Bargaining Solution.

❓ 5: Game Classification
Based on the interests mapped, is this game:
- Coordination (both want deal, need to align)
```

## 10. Leverage-Modified Minimax Solver

### 10.1 Overview

The standard MinimaxSolver (from v2.1) serves as the base. The LeverageModifiedMinimaxSolver extends it with:

1. **Leverage multipliers** on utility calculations
2. **BATNA floor protection** on worst-case scenarios
3. **Red line enforceability validation**
4. **Confidence adjustment** based on leverage stability
5. **Leverage strategy** in recommendations

### 10.2 Complete Leverage-Modified Solver

```python
class LeverageModifiedMinimaxSolver(MinimaxSolver):
    """
    Minimax solver enhanced with leverage mapping integration.
    Extends the standard MinimaxSolver from v2.1.
    
    Modifications from standard solver:
    1. Utility calculations adjusted by leverage multipliers
    2. Worst-case floors protected by BATNA
    3. Red line enforceability validated against leverage
    4. Confidence adjusted by leverage stability
    5. Recommendations include leverage strategy
    """
    
    def __init__(self, user_profile: Dict, leverage_map: 'LeverageMap'):
        # Initialize parent (standard solver)
        super().__init__(user_profile)
        
        # Leverage integration
        self.leverage_map = leverage_map
        self.leverage_integration = LeverageIntegrationManager(leverage_map)
    
    def solve(self, phase3_output: Dict) -> Dict:
        """
        Implements leverage-modified minimax:
        
        v_i = max_{a_i} min_{a_{-i}} [v_i(a_i, a_{-i}) × L(a_i)]
        
        Where L(a_i) is the leverage multiplier for action a_i.
        """
        choices = phase3_output["choices"]
        choice_evaluations = []
        
        for choice in choices:
            evaluation = self._evaluate_choice_with_leverage(choice)
            choice_evaluations.append(evaluation)
        
        # Apply leverage-modified minimax selection
        best_choice = self._leverage_minimax_select(choice_evaluations)
        
        # Calculate leverage-adjusted confidence
        confidence = self._calculate_leverage_confidence(
            best_choice, choice_evaluations
        )
        
        # Generate leverage strategy for recommendation
        leverage_strategy = self._generate_leverage_strategy(best_choice)
        
        return {
            "analysis": [
                self._evaluation_to_dict(e) for e in choice_evaluations
            ],
            "recommendation": best_choice,
            "confidence": confidence,
            "leverage_strategy": leverage_strategy,
            "worst_case_comparison": self._compare_to_baseline(best_choice),
            "audit_trail": {
                "weights_used": self.weights,
                "red_lines_checked": self.red_lines,
                "risk_parameters": self.risk_params,
                "leverage_applied": {
                    "total_leverage_points": len(self.leverage_map.leverage_points),
                    "hidden_leverage_used": len(self.leverage_map.hidden_leverage),
                    "batna_floor_applied": True,
                    "leverage_multipliers_applied": True
                }
            }
        }
    
    def _evaluate_choice_with_leverage(
        self, choice: Dict
    ) -> 'LeverageAdjustedChoiceEvaluation':
        """
        Evaluates all branches with leverage adjustments applied.
        """
        branches = choice["branches"]
        branch_evaluations = []
        
        for branch in branches:
            # Calculate base utility vector (from parent class)
            utility_vector = {}
            for dimension, impact in branch["utility_impact"].items():
                utility_vector[dimension] = self._calculate_dimension_utility(
                    dimension, impact
                )
            
            # Apply leverage multipliers (NEW)
            leverage_multiplier = self._calculate_branch_leverage_multiplier(
                choice["choice_id"], branch
            )
            
            # Check for red line violations (with enforceability check)
            red_line_violation = self._check_red_lines_with_leverage(branch)
            
            # Calculate weighted utility with leverage adjustment
            if red_line_violation:
                # Check if red line is actually enforceable
                enforceability = self.leverage_integration.validate_red_line_enforceability(
                    self._identify_violated_red_line(branch)
                )
                
                if enforceability.enforceable:
                    weighted_utility = -1.0  # Hard constraint
                else:
                    # Red line is a bluff; soften the penalty
                    weighted_utility = -0.7  # Reduced penalty
            else:
                weighted_utility = sum(
                    self.weights.get(dim, 0) * util 
                    for dim, util in utility_vector.items()
                )
                
                # Apply leverage multiplier (NEW)
                weighted_utility *= leverage_multiplier
            
            # Apply loss aversion (from parent class)
            if weighted_utility < 0:
                weighted_utility *= self.risk_params["loss_aversion_factor"]
                weighted_utility = max(-1.0, weighted_utility)
            
            # Apply BATNA floor protection to worst case (NEW)
            if branch["scenario"] == "worst":
                weighted_utility = self.leverage_integration.modify_minimax_worst_case(
                    choice["choice_id"], weighted_utility
                )
            
            branch_eval = BranchEvaluation(
                branch_id=branch["scenario"],
                utility_vector=utility_vector,
                weighted_utility=weighted_utility,
                red_line_violation=red_line_violation,
                reversible=branch.get("reversible", False),
                leverage_multiplier=leverage_multiplier
            )
            
            branch_evaluations.append(branch_eval)
        
        # Find worst case (from parent class logic)
        worst_case = min(branch_evaluations, key=lambda b: b.weighted_utility)
        
        # Calculate reversibility bonus (from parent class)
        reversibility_bonus = 0.1 if worst_case.reversible else 0.0
        
        return LeverageAdjustedChoiceEvaluation(
            choice_id=choice["choice_id"],
            choice_description=choice["description"],
            branch_evaluations=branch_evaluations,
            worst_case=worst_case,
            worst_case_utility=worst_case.weighted_utility,
            reversibility_bonus=reversibility_bonus,
            adjusted_worst_case=worst_case.weighted_utility + reversibility_bonus,
            leverage_summary=self._summarize_choice_leverage(choice["choice_id"])
        )
    
    def _calculate_branch_leverage_multiplier(
        self, choice_id: str, branch: Dict
    ) -> float:
        """
        Calculates the leverage multiplier for a specific branch.
        Different scenarios may be affected differently by leverage.
        """
        applicable_leverage = self.leverage_map.get_applicable_leverage(choice_id)
        
        total_multiplier = 1.0
        
        for leverage in applicable_leverage:
            # Different leverage types affect different scenarios differently
            if branch["scenario"] == "worst":
                # BATNA and resources improve worst case
                if leverage.domain in ["structural", "resource"]:
                    multiplier = 1 + (leverage.strength - 3) * 0.1
                    total_multiplier *= multiplier
                    
            elif branch["scenario"] == "likely":
                # Negotiation leverage improves likely case
                if leverage.domain in ["negotiation", "informational"]:
                    multiplier = 1 + (leverage.strength - 3) * 0.08
                    total_multiplier *= multiplier
                    
            elif branch["scenario"] == "best":
                # All leverage types can improve best case
                multiplier = 1 + (leverage.strength - 3) * 0.05
                total_multiplier *= multiplier
        
        # Cap the multiplier to reasonable bounds
        return min(max(total_multiplier, 0.5), 2.0)
    
    def _check_red_lines_with_leverage(self, branch: Dict) -> bool:
        """
        Checks red lines AND validates their enforceability.
        A red line without enforcement leverage is a bluff.
        """
        for red_line in self.red_lines:
            if red_line in branch.get("red_line_risks", []):
                # Check if this red line is enforceable
                validation = self.leverage_integration.validate_red_line_enforceability(
                    red_line
                )
                
                # Even if not enforceable, still flag it but with lower penalty
                return True  # Still a violation, but penalty may be reduced
        
        return False
    
    def _identify_violated_red_line(self, branch: Dict) -> str:
        """Identify which red line is violated"""
        for red_line in self.red_lines:
            if red_line in branch.get("red_line_risks", []):
                return red_line
        return ""
    
    def _leverage_minimax_select(
        self, evaluations: List['LeverageAdjustedChoiceEvaluation']
    ) -> Dict:
        """
        Selects choice with highest leverage-adjusted worst-case.
        Includes leverage strategy in recommendation.
        """
        sorted_evals = sorted(
            evaluations,
            key=lambda e: e.adjusted_worst_case,
            reverse=True
        )
        
        best = sorted_evals[0]
        
        # Generate leverage strategy
        leverage_strategy = self._generate_leverage_strategy(best)
        
        return {
            "selected_choice": best.choice_id,
            "selection_rationale": (
                f"Worst-case utility: {best.worst_case_utility:.2f} "
                f"(+{best.reversibility_bonus:.1f} reversibility bonus). "
                f"Leverage multiplier applied: {best.leverage_summary['average_multiplier']:.2f}. "
                f"This choice has the highest leverage-adjusted floor."
            ),
            "leverage_strategy": leverage_strategy,
            "all_worst_cases": [
                {
                    "choice": e.choice_id,
                    "worst_case_utility": e.worst_case_utility,
                    "leverage_multiplier": e.leverage_summary["average_multiplier"],
                    "adjusted_worst_case": e.adjusted_worst_case
                }
                for e in sorted_evals
            ]
        }
    
    def _generate_leverage_strategy(
        self, best_choice: 'LeverageAdjustedChoiceEvaluation'
    ) -> Dict:
        """
        Generates actionable leverage strategy for the recommended choice.
        Tells the user HOW to use their leverage.
        """
        applicable = self.leverage_map.get_applicable_leverage(
            best_choice.choice_id
        )
        
        strategy = {
            "primary_leverage": [],
            "secondary_leverage": [],
            "timing_recommendations": [],
            "tactical_advice": [],
            "risk_warnings": []
        }
        
        # Sort leverage by strength
        sorted_leverage = sorted(applicable, key=lambda lp: lp.strength, reverse=True)
        
        for i, leverage in enumerate(sorted_leverage):
            if i == 0:
                strategy["primary_leverage"].append({
                    "leverage": leverage.description,
                    "strength": leverage.strength,
                    "how_to_use": self._get_leverage_usage_advice(leverage),
                    "timing": self._get_leverage_timing(leverage)
                })
            elif i <= 2:
                strategy["secondary_leverage"].append({
                    "leverage": leverage.description,
                    "strength": leverage.strength,
                    "how_to_use": self._get_leverage_usage_advice(leverage)
                })
        
        # Add timing recommendations
        ephemeral_leverage = [
            lp for lp in applicable if lp.durability == "ephemeral"
        ]
        for lp in ephemeral_leverage:
            strategy["timing_recommendations"].append(
                f"Use {lp.description} soon - it's time-limited"
            )
        
        # Add tactical advice
        if any(lp.user_aware == False for lp in applicable):
            strategy["tactical_advice"].append(
                "You have hidden leverage. Don't reveal all your cards at once."
            )
        
        # Add risk warnings
        decreasing_leverage = self.leverage_map.leverage_trajectory.decreasing
        if decreasing_leverage:
            strategy["risk_warnings"].append(
                f"Some leverage is decreasing: {', '.join(decreasing_leverage)}"
            )
        
        return strategy
    
    def _get_leverage_usage_advice(self, leverage: 'LeveragePoint') -> str:
        """Get tactical advice for using specific leverage"""
        advice_map = {
            "BATNA": "Mention alternatives without threatening",
            "time_asymmetry": "Don't rush; let time work in your favor",
            "counterparty_constraints": "Let their deadline pressure build",
            "financial_runway": "You can afford to wait; don't signal urgency"
        }
        return advice_map.get(leverage.type, "Use judiciously")
    
    def _get_leverage_timing(self, leverage: 'LeveragePoint') -> str:
        """Get timing advice for leverage usage"""
        if leverage.durability == "ephemeral":
            return f"Use immediately - expires soon"
        elif leverage.durability == "situational":
            return f"Use during this specific situation"
        else:
            return f"Available long-term"
    
    def _calculate_leverage_confidence(
        self, best_choice, all_evaluations
    ) -> Dict:
        """Calculate confidence adjusted by leverage stability"""
        # Base confidence from parent class
        base_confidence = self._calculate_confidence(best_choice, all_evaluations)
        
        # Adjust by leverage stability
        ephemeral_count = len([
            lp for lp in self.leverage_map.leverage_points
            if lp.durability == "ephemeral"
        ])
        
        if ephemeral_count > 2:
            stability = "low"
            adjustment = -1  # Reduce confidence
        elif ephemeral_count > 0:
            stability = "moderate"
            adjustment = 0
        else:
            stability = "high"
            adjustment = 1  # Increase confidence
        
        # Apply adjustment
        if base_confidence == "HIGH" and adjustment == -1:
            adjusted = "MEDIUM"
        elif base_confidence == "MEDIUM" and adjustment == 1:
            adjusted = "HIGH"
        else:
            adjusted = base_confidence
        
        return {
            "level": adjusted,
            "base_confidence": base_confidence,
            "leverage_stability": stability,
            "hidden_leverage_confidence": self._calculate_hidden_leverage_confidence()
        }
    
    def _calculate_hidden_leverage_confidence(self) -> float:
        """Calculate confidence in hidden leverage discoveries"""
        if not self.leverage_map.hidden_leverage:
            return 1.0
        
        total_confidence = sum(
            hl.leverage_point.confidence 
            for hl in self.leverage_map.hidden_leverage
        )
        return total_confidence / len(self.leverage_map.hidden_leverage)
    
    def _summarize_choice_leverage(self, choice_id: str) -> Dict:
        """Summarize leverage applicable to a choice"""
        applicable = self.leverage_map.get_applicable_leverage(choice_id)
        
        if not applicable:
            return {
                "average_multiplier": 1.0,
                "applicable_leverage": 0,
                "hidden_leverage_used": 0
            }
        
        multipliers = [
            1 + (lp.strength - 3) * 0.2 
            for lp in applicable
        ]
        
        return {
            "average_multiplier": sum(multipliers) / len(multipliers),
            "applicable_leverage": len(applicable),
            "hidden_leverage_used": len([
                lp for lp in applicable if not lp.user_aware
            ])
        }
```

```python
class DeterministicHiddenLeverageDetector:
    """
    Implements six research-based pattern detection algorithms.
    Each pattern is grounded in peer-reviewed cognitive bias research.
    """
    
    def __init__(self):

            self._detect_batna_underestimation,

            self._detect_time_asymmetry_blindness,

    def _detect_batna_underestimation(
        self, phase1_output: Dict, emergent_leverage: List['LeveragePoint']
    ) -> List['HiddenLeverageDiscovery']:
        """
        PATTERN 1: BATNA Underestimation
        
        Research Basis:
        - Kahneman & Tversky (1979) "Prospect Theory"
          → Anchoring bias causes people to underestimate alternatives
        - Tversky & Kahneman (1974) "Judgment under Uncertainty"
          → Availability heuristic: recent vivid events overweighted
        - Northcraft & Neale (1987) → Anchoring in negotiations
        
        Detection Logic:
        1. Extract user's stated alternatives
        2. Calculate actual alternatives from context (skills, network, market)
        3. If actual > stated + threshold, hidden leverage exists
        """
        discoveries = []
        
        # Get user's stated alternatives
        stated_alternatives = phase1_output.get(
            "leverage_precursors", {}
        ).get("user_stated_alternatives", [])
        
        # Calculate actual alternatives from multiple sources
        actual_alternatives = self._calculate_actual_alternatives(phase1_output)
        
        # Calculate gap
        if len(actual_alternatives) > len(stated_alternatives) + 1:
            gap_size = len(actual_alternatives) - len(stated_alternatives)
            
            # Assess strength based on gap and quality of alternatives
            strength = min(5.0, 3.0 + gap_size * 0.5)
            
            # Adjust for alternative quality
            quality_multiplier = self._assess_alternative_quality(
                actual_alternatives, phase1_output
            )
            strength *= quality_multiplier
            
            discoveries.append(HiddenLeverageDiscovery(

                    domain="structural",
                    type="BATNA",
```

```python
class EmergentDiscoveryEngine:
    """
    Uses LLM ideation to discover hidden leverage that
    deterministic patterns might miss.
    """
    
    def __init__(self, llm_client):
        self.llm = llm_client
    
    def discover(
        self,
        phase1_output: Dict,
        emergent_leverage: List['LeveragePoint'],
        deterministic_findings: List['HiddenLeverageDiscovery']
    ) -> List['HiddenLeverageDiscovery']:
        """
        Discovers novel hidden leverage through emergent questioning.
        Uses five discovery strategies grounded in creative thinking research.
        """
        
        # Strategy 1: Counterfactual Analysis
        counterfactual_findings = self._counterfactual_analysis(
            phase1_output, deterministic_findings
        )
        
        # Strategy 2: Perspective Reversal
        reversal_findings = self._perspective_reversal(
            phase1_output, deterministic_findings
        )
        
        # Strategy 3: Temporal Shifting
        temporal_findings = self._temporal_shifting(
            phase1_output, deterministic_findings
        )
        
        # Strategy 4: Constraint Removal
        constraint_findings = self._constraint_removal(
            phase1_output, deterministic_findings
        )
        
        # Strategy 5: Analogical Reasoning
        analogical_findings = self._analogical_reasoning(
            phase1_output, deterministic_findings
        )
        
        # Combine all findings
        all_findings = (
            counterfactual_findings +
            reversal_findings +
            temporal_findings +
            constraint_findings +
            analogical_findings
        )
        
        # Deduplicate
        return self._deduplicate_findings(all_findings)
    
    def _counterfactual_analysis(

        - Roese (1997) "Counterfactual thinking"

        CONTEXT:
        {json.dumps(phase1_output, indent=2)}

        Scenario: [counterfactual question]
        Hidden Leverage: [what emerges]
        Strength: [1-5]
        How to Activate: [practical advice]
        """

    def _perspective_reversal(
        self, phase1_output: Dict, known_findings: List
    ) -> List['HiddenLeverageDiscovery']:
        """
        Strategy 2: "If I were them, what would worry me?"

        - Galinsky et al. (2008) "Why it pays to get inside the head of your opponent"
        - Perspective-taking in negotiation research
        """
        prompt = f"""
        CONTEXT:
        {json.dumps(phase1_output, indent=2)}
        
        KNOWN HIDDEN LEVERAGE (avoid duplicating):
        {self._format_known_findings(known_findings)}
        
        PERSPECTIVE REVERSAL:

        1. "What would worry me about this user?"
        2. "What would make me replace this user?"
        3. "What would I be afraid the user might do?"
        4. "What alternatives do I fear the user has?"
        
        Each worry or fear from the counterparty's perspective
        reveals leverage the user may not know they have.
        
        FORMAT:

        Revealed User Leverage: [what this means user has]
```

### 11.4 Hybrid Validation Engine (Complete Implementation)

```python
class HybridValidationEngine:
    """
    Validates hidden leverage discoveries through cross-validation.
    Ensures discoveries are:
    1. Research-grounded (based on validated patterns)
    2. Contextually appropriate (fit this specific situation)
    3. Practically actionable (user can actually use it)
    """
    
    def __init__(self):
        self.research_validators = {
            "structural": self._validate_structural_finding,
            "psychological": self._validate_psychological_finding,
            "informational": self._validate_informational_finding,
            "resource": self._validate_resource_finding
        }
    
    def validate(
        self,
        deterministic_findings: List['HiddenLeverageDiscovery'],
        emergent_findings: List['HiddenLeverageDiscovery'],
        context: Dict
    ) -> List['ValidatedHiddenLeverage']:
        """
        Validates and consolidates all hidden leverage discoveries.
        """
        validated = []
        
        # Validate deterministic findings (higher confidence threshold)
        for finding in deterministic_findings:
            validation_score = self._validate_finding(finding, context)
            if validation_score > 0.7:
                validated.append(ValidatedHiddenLeverage(
                    finding=finding,
                    validation_score=validation_score,
                    validation_method="deterministic",
                    cross_validated=True
                ))
        
        # Validate emergent findings (lower threshold, but require cross-validation)
        for finding in emergent_findings:
            validation_score = self._validate_finding(finding, context)
            
            # Emergent findings need cross-validation with deterministic patterns
            cross_validation = self._cross_validate_with_patterns(finding)
            
            combined_score = validation_score * 0.6 + cross_validation * 0.4
            
            if combined_score > 0.5:
                validated.append(ValidatedHiddenLeverage(
                    finding=finding,
                    validation_score=combined_score,
                    validation_method="emergent_cross_validated",
                    cross_validated=cross_validation > 0.5
                ))
        
        # Merge and deduplicate
        return self._merge_and_dedupe(validated)
    
    def _validate_finding(
        self, finding: 'HiddenLeverageDiscovery', context: Dict
    ) -> float:
        """
        Validates a finding against:
        1. Research basis (is this grounded in science?)
        2. Context fit (does this apply to this situation?)
        3. Practicality (can user actually use this?)
        """
        # Research validation (0-1)
        research_score = self._assess_research_basis(finding)
        
        # Context validation (0-1)
        context_score = self._assess_context_fit(finding, context)
        
        # Practicality validation (0-1)
        practicality_score = self._assess_practicality(finding, context)
        
        # Weighted combination
        return research_score * 0.4 + context_score * 0.4 + practicality_score * 0.2
    
    def _assess_research_basis(self, finding) -> float:
        """Assess how well-grounded the finding is in research"""
        if finding.leverage_point.research_basis:
            # Check if research basis is from validated research
            validated_sources = [
                "Kahneman", "Tversky", "Cialdini", "Emerson", 
                "Akerlof", "Burt", "Fisher", "Ury"
            ]
            if any(source in finding.leverage_point.research_basis for source in validated_sources):
                return 0.9
            return 0.6
        return 0.3
    
    def _assess_context_fit(self, finding, context) -> float:
        """Assess how well the finding fits this specific context"""
        # Check if evidence supports the finding
        if finding.leverage_point.evidence:
            return 0.8
        return 0.5
    
    def _assess_practicality(self, finding, context) -> float:
        """Assess whether user can practically use this leverage"""
        if finding.leverage_point.enforceable:
            return 0.9
        return 0.3
    
    def _cross_validate_with_patterns(self, finding) -> float:
        """Cross-validate emergent findings with deterministic patterns"""
        # Check if emergent finding aligns with known patterns
        pattern_alignment = 0.5  # Default
        
        # Map leverage types to patterns
        type_pattern_map = {
            "BATNA": "undervalued_batna",
            "uniqueness": "unrecognized_scarcity",
            "time_asymmetry": "time_asymmetry_blindness"
        }
        
        finding_type = finding.leverage_point.type
        if finding_type in type_pattern_map:
            pattern_alignment = 0.8
        
        return pattern_alignment
```

## 12. Epistemic Halt Mechanism

### 12.1 Trigger Conditions

The LLM must trigger an Epistemic Halt when:

1. **Missing Utility Weighting**: User-specific preference unknown
2. **Ambiguous Stakeholder Intent**: Other party's true motivation unclear
3. **Missing Dependency Definition**: Critical dependency unstated
4. **Speculation Required**: No CONTEXT or FRAMEWORK basis available
5. **Leverage Awareness Unknown** (v3.1): User doesn't know if they have leverage
6. **Counterparty Constraint Unknown** (v3.1): Critical constraint information missing

### 12.2 HALT Format Specification

```
<<<HALT>>>
PHASE: [1|1.5|2|3]
ROUND: [N]
BLOCKING_NODE: [the question you cannot answer]
WHY_BLOCKED: [why neither CONTEXT nor FRAMEWORK resolves this]
IMPACT_IF_ASSUMED: [how the decision tree or utility function
would be corrupted by guessing]
USER_QUESTION:
❓ 1: [Title]
[Question in plain language the user will understand]
➡️ Recommended: [Tentative answer + confidence: LOW/MEDIUM]
<<<END_HALT>>>
```

### 12.3 Halt Processing Flow

```mermaid
flowchart TD
    A[Internal Grilling Round N] --> B{Evaluate Frontier}
    B --> C[Generate Next Question]
    
    C --> D{Can this question be<br/>answered from existing<br/>context or research?}
    
    D -- Yes --> E[LLM Answers Internally<br/>➡️ Recommended Answer]
    E --> F[Advance Design Tree]
    
    D -- No --> G[🛑 EPISTEMIC HALT]
    G --> H[Step Out: Ask User]
    
    H --> I[Format Question using Grill-Me<br/>❓ + ➡️ Recommended]
    I --> J[Pause Internal Loop]
    J --> K[User Provides Answer]
    
    K --> L[Update Context & Glossary]
    L --> M[Resume Internal Loop<br/>from Halted Node]
    M --> B
```

```python
class HaltManager:
    def __init__(self):

        self.active_halt = None

            "user_answer": user_answer,
            "resolved_at": datetime.now().isoformat()

            "why_asking": halt['why_blocked'],
            "impact": halt['impact_if_assumed'],
            "question": halt['user_question'],
            "recommended_answer": halt['user_question']['recommended']
        }
```

### 13.4 Leverage-Aware Utility Calculator (NEW in v3.1)

```python
class LeverageAwareUtilityCalculator:
    """
    Utility calculator that incorporates leverage multipliers.
    """
    
    def __init__(self, user_profile: Dict, leverage_map: 'LeverageMap'):
        self.profile = user_profile
        self.leverage_map = leverage_map
    
    def calculate_utility(
        self, 
        choice_id: str, 
        scenario: str, 
        base_utility: float
    ) -> float:
        """
        Calculates leverage-adjusted utility for a choice/scenario.
        """
        # Get applicable leverage for this choice
        applicable = self.leverage_map.get_applicable_leverage(choice_id)
        
        # Calculate leverage multiplier
        multiplier = self._calculate_scenario_multiplier(applicable, scenario)
        
        # Apply BATNA floor for worst case
        if scenario == "worst":
            base_utility = self._apply_batna_floor(applicable, base_utility)
        
        # Apply multiplier
        adjusted_utility = base_utility * multiplier
        
        # Ensure bounds
        return max(-1.0, min(1.0, adjusted_utility))
    
    def _calculate_scenario_multiplier(self, leverage_points, scenario):
        """Calculate leverage multiplier for a specific scenario"""
        multiplier = 1.0
        
        for lp in leverage_points:
            if scenario == "worst" and lp.domain in ["structural", "resource"]:
                multiplier *= 1 + (lp.strength - 3) * 0.1
            elif scenario == "likely" and lp.domain in ["negotiation", "informational"]:
                multiplier *= 1 + (lp.strength - 3) * 0.08
            elif scenario == "best":
                multiplier *= 1 + (lp.strength - 3) * 0.05
        
        return min(max(multiplier, 0.5), 2.0)
    
    def _apply_batna_floor(self, leverage_points, current_worst_case):
        """Apply BATNA floor protection"""
        for lp in leverage_points:
            if lp.batna and lp.enforceable:
                batna_floor = -lp.strength * 0.15
                current_worst_case = max(current_worst_case, batna_floor)
        return current_worst_case
```

```python
    def __init__(self, storage_system, user_id):
        self.storage = storage_system
        self.user_id = user_id
        self.profile = self._load_profile()
        
    def _load_profile(self):
        """Load user profile from qmd storage"""
        results = self.storage.retrieve_relevant_context(
            f"user_profile user_id:{self.user_id}",
            user_id=self.user_id,
            collection="user_profiles"
        )
        
        if results:
            return self._parse_profile_markdown(results[0]['content'])
        else:
            return self._initialize_new_profile()
            
    def make_decision(self, situation_context):
        """Complete decision-making process with qmd-backed context"""
        
        # Step 1: Retrieve relevant past decisions
        past_decisions = self.storage.retrieve_relevant_context(
            f"decision_tree similar_to:{situation_context['type']}",
            user_id=self.user_id,
            collection="decision_trees"
        )
        
        # Step 2: Retrieve similar leverage maps
        similar_leverage = self.storage.retrieve_relevant_context(
            f"leverage_map similar_to:{situation_context['type']}",
            user_id=self.user_id,
            collection="leverage_maps"
        )
        
        # Step 3: Build complete context
        complete_context = {
            "user_profile": self.profile,
            "situation_context": situation_context,
            "past_decisions": past_decisions,
            "similar_leverage": similar_leverage
        }
        
        # Step 4: Run pipeline
        result = self._run_pipeline(complete_context)
        
        # Step 5: Store outcomes
        self._store_outcomes(result)
        
        return result
```

## 15. Orchestrator Implementation

### 15.1 The Emergent Orchestrator (Complete Implementation)

```python
import json
import re
from typing import Dict, List, Optional
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum

class OutputType(Enum):
    INTERNAL_ANSWER = "internal_answer"
    HALT = "halt"
    COMPLETE = "complete"
    INSUFFICIENT_CONTEXT = "insufficient_context"

@dataclass
class RoundResult:
    questions: List[dict] = field(default_factory=list)
    answers: List[dict] = field(default_factory=list)
    halts: List[dict] = field(default_factory=list)
    round_number: int = 0
    phase: int = 0
    frontier_complete: bool = False

class EmergentOrchestrator:
    """
    Orchestrates the four phases including Leverage Mapping.
    Each phase runs its own emergent grilling session.
    """
    
    def __init__(self, llm_client, storage_system, user_profile):
        self.llm = llm_client
        self.storage = storage_system
        self.profile = user_profile
        self.halt_manager = HaltManager()
        
    def run_decision(self, initial_context: dict) -> dict:
        """Run complete decision pipeline with leverage mapping"""
        
        # Phase 1: Context Ingestion
        phase1_engine = EmergentGrillingEngine(
            llm_client=self.llm,
            objective="Build complete context for decision",
            mode="grill-me"
        )
        phase1_result = phase1_engine.run_session(initial_context)
        
        # Phase 1.5: Leverage Mapping (NEW in v3.1)
        leverage_engine = LeverageMappingEngine(
            llm_client=self.llm,
            phase1_output=phase1_result,
            user_profile=self.profile
        )
        leverage_map = leverage_engine.run_leverage_mapping()
        
        # Phase 2: Game Theory Analysis (Leverage-Enhanced)
        phase2_engine = EmergentGrillingEngine(
            llm_client=self.llm,
            objective="Determine if win-win possible",
            mode="grill-with-docs"
        )
        phase2_context = self._enhance_with_leverage(
            phase1_result, leverage_map
        )
        phase2_result = phase2_engine.run_session(phase2_context)
        
        # Check if win-win found
        if phase2_result.get("pareto_analysis", {}).get("win_win_possible"):
            return self._format_win_win_recommendation(
                phase2_result, leverage_map
            )
        
        # Phase 3: Minimax Analysis (Leverage-Adjusted)
        phase3_engine = EmergentGrillingEngine(
            llm_client=self.llm,
            objective="Generate complete decision tree",
            mode="grill-me"
        )
        phase3_context = self._enhance_with_leverage(
            phase2_result, leverage_map
        )
        phase3_result = phase3_engine.run_session(phase3_context)
        
        # Leverage-Modified Minimax Calculation
        solver = LeverageModifiedMinimaxSolver(
            user_profile=self.profile,
            leverage_map=leverage_map
        )
        recommendation = solver.solve(phase3_result)
        
        # Store decision outcome
        self._store_decision_outcome(
            initial_context,
            phase1_result,
            leverage_map,
            phase2_result,
            phase3_result,
            recommendation
        )
        
        return recommendation
    
    def _enhance_with_leverage(
        self, context: dict, leverage_map: 'LeverageMap'
    ) -> dict:
        """Adds leverage information to context for downstream phases"""
        context["leverage_map"] = leverage_map
        context["user_total_leverage"] = leverage_map.stakeholder_leverage["user"].total_strength
        context["hidden_leverage_count"] = len(leverage_map.hidden_leverage)
        context["dominant_leverage_domains"] = leverage_map.stakeholder_leverage["user"].dominant_domains
        return context
    
    def _format_win_win_recommendation(
        self, phase2_result: dict, leverage_map: 'LeverageMap'
    ) -> dict:
        """Format win-win recommendation with leverage context"""
        pareto = phase2_result["pareto_analysis"]["pareto_improvement"]
        
        return {
            "type": "win_win",
            "recommendation": pareto["description"],
            "leverage_strategy": {
                "user_leverage": leverage_map.stakeholder_leverage["user"].total_strength,
                "leverage_used": pareto.get("leverage_used", []),
                "strategic_recommendations": leverage_map.strategic_recommendations
            },
            "user_gains": pareto["user_gains"],
            "counterparty_gains": pareto["client_gains"]
        }
    
    def _store_decision_outcome(
        self, initial_context, phase1, leverage_map, phase2, phase3, recommendation
    ):
        """Store complete decision record for future retrieval"""
        
        decision_id = f"{datetime.now().strftime('%Y-%m-%d')}_{initial_context.get('type', 'general')}"
        
        # Store decision tree
        self.storage.store_decision_tree(decision_id, {
            "decision_id": decision_id,
            "date": datetime.now().isoformat(),
            "description": initial_context.get("description", ""),
            "phase1": phase1,
            "phase2": phase2,
            "phase3": phase3,
            "recommendation": recommendation
        })
        
        # Store leverage map
        self.storage.store_leverage_map(decision_id, leverage_map)
        
        # Store interview logs
        session_id = f"{datetime.now().strftime('%Y%m%d_%H%M%S')}"
        self.storage.store_interview_log(session_id, {
            "decision_id": decision_id,
            "phase1_session": phase1.get("session_metadata", {}),
            "phase2_session": phase2.get("session_metadata", {}),
            "phase3_session": phase3.get("session_metadata", {})
        })
```

```
# ROLE
You are the Grilling Agent in a Deterministic Decision Engine with
Leverage Mapping. You conduct structured interviews using the grilling

# THE PROTOCOL

## Design Tree
You model the subject as a design tree: every decision branches into
the decisions that hang off it. Your job is to interview until nothing
is left silently assumed.

## Frontier Calculation
Each round, you:
1. Identify all decisions whose prerequisites are settled
2. Generate questions for ALL of them (the frontier)
3. Never ask a question that depends on an unsettled question
4. Two questions never share a round if one depends on the other

## Question Format
Every question arrives in this exact shape:
❓ [number]: [Title]
[Question body specific to this decision context]
➡️ Recommended: [Your best answer based on available context]

If you can answer from context or a validated framework, provide your
recommended answer with basis. If you cannot answer without user input,
mark the recommendation as "USER_INPUT_REQUIRED" and explain why.

## Facts vs. Decisions
- FACTS: You answer these yourself from context or research. Do not
  ask the user something you can find out.
- DECISIONS: These require user input. Mark as USER_INPUT_REQUIRED
  and provide your best recommendation with low confidence.

## Leverage Awareness
During interviews, actively look for:
1. Undervalued BATNA (user has alternatives they don't count)
2. Unrecognized scarcity (user is unique but doesn't realize)
3. Time asymmetry blindness (user can wait but thinks they can't)
4. Dependency misreading (counterparty needs user more than user thinks)
5. Information asymmetry unawareness (user knows valuable things)
6. Network position blindness (user occupies structural hole)

When you detect potential hidden leverage, note it explicitly and
ask follow-up questions to validate.

## Rounds
- Ask the ENTIRE frontier in one round
- Update the design tree based on answers
- Recalculate the frontier
- Repeat until frontier is empty
- The number of rounds is EMERGENT, not fixed
- The number of questions is EMERGENT, not capped

## Termination
Stop when:
1. Frontier is empty (all decisions settled)
2. User confirms shared understanding
3. Scope too large (escalate to multi-session)

# JUSTIFICATION REQUIREMENTS (NON-NEGOTIABLE)
Every answer must cite its BASIS, one of exactly three:
- CONTEXT: Directly stated in the structured context object (cite field)
- FRAMEWORK: A validated model (name it: e.g., "Nash Bargaining Solution",
  "vNM utility construction", "Minimax regret principle")
- USER_INPUT: Obtained via Epistemic Halt

If you cannot cite one of these three, you are speculating.
Speculation triggers an EPISTEMIC HALT.

# EPISTEMIC HALT PROTOCOL
When a frontier question cannot be answered via CONTEXT or FRAMEWORK:
<<<HALT>>>
PHASE: [1|1.5|2|3]
ROUND: [N]
BLOCKING_NODE: [the question]
WHY_BLOCKED: [why neither CONTEXT nor FRAMEWORK resolves this]
IMPACT_IF_ASSUMED: [how the tree would be corrupted by guessing]
USER_QUESTION:
❓ 1: [Title]
[Question in plain language]
➡️ Recommended: [Tentative answer + confidence: LOW/MEDIUM]
<<<END_HALT>>>

# OUTPUT CONTRACT
When the frontier is exhausted, emit ONLY a JSON object conforming to
the schema provided. No prose. No explanation outside the JSON.

# FORBIDDEN
- Using predetermined question lists
- Generic questions not specific to this decision
- Asking about facts you could find out yourself
- Acting on decisions without user confirmation
- Writing to files without explicit grill-with-docs mode
- Capping the number of questions or rounds
- Silently assuming user preferences, facts, or probabilities
- Ignoring potential hidden leverage signals
```

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import Optional, List
import uuid

app = FastAPI(title="ADIE API", version="3.1.0")

class DecisionRequest(BaseModel):
    user_id: str
    situation_description: str
    choices: List[str]
    context: Optional[dict] = None

class InterviewResponse(BaseModel):
    session_id: str
    phase: str  # "1" | "1.5" | "2" | "3"
    round: int
    questions: Optional[List[dict]] = None
    leverage_map: Optional[dict] = None
    recommendation: Optional[dict] = None
    status: "interviewing" | "processing" | "complete" | "halted"

@app.post("/decisions/start", response_model=InterviewResponse)
async def start_decision(request: DecisionRequest):
    """Initialize a new decision session"""
    
    session_id = str(uuid.uuid4())
    
    # Load user profile
    profile = await load_user_profile(request.user_id)
    
    # Initialize orchestrator
    orchestrator = EmergentOrchestrator(
        llm_client=llm_client,
        storage_system=qmd_storage,
        user_profile=profile
    )
    
    # Start Phase 1
    result = await orchestrator.run_decision(request.dict())
    
    return InterviewResponse(
        session_id=session_id,
        phase=result.get("phase", "1"),
        round=result.get("round", 1),
        status=result.get("status", "interviewing"),
        questions=result.get("questions"),
        leverage_map=result.get("leverage_map"),
        recommendation=result.get("recommendation")
    )

@app.post("/decisions/{session_id}/answer", response_model=InterviewResponse)
async def submit_answer(session_id: str, answer: dict):
    """Submit answer to interview question or halt"""
    
    orchestrator = await get_orchestrator(session_id)
    
    # Process answer
    result = await orchestrator.process_answer(answer)
    
    return InterviewResponse(
        session_id=session_id,
        phase=result.get("phase", ""),
        round=result.get("round", 0),
        status=result.get("status", "processing"),
        questions=result.get("questions"),
        leverage_map=result.get("leverage_map"),
        recommendation=result.get("recommendation")
    )

@app.get("/decisions/{session_id}/status")
async def get_status(session_id: str):
    """Get current status of decision session"""
    
    orchestrator = await get_orchestrator(session_id)
    
    return {
        "session_id": session_id,
        "current_phase": orchestrator.current_phase,
```

```python
        logger.info(
            "hidden_leverage_discovered",
            session_id=self.session_id,
            pattern_type=discovery.get("pattern_type"),
            leverage_strength=discovery["leverage_point"].strength,
            awareness_gap=discovery["awareness_gap"],
            timestamp=datetime.now().isoformat()
        )
    
    def log_leverage_map_generated(self, leverage_map):
        logger.info(
            "leverage_map_generated",
            session_id=self.session_id,
            total_leverage_points=len(leverage_map.leverage_points),
            hidden_leverage_count=len(leverage_map.hidden_leverage),
            user_total_leverage=leverage_map.stakeholder_leverage["user"].total_strength,
            timestamp=datetime.now().isoformat()
        )
    
    def log_decision_made(self, recommendation: dict):
        logger.info(
            "decision_made",
            session_id=self.session_id,
            selected_choice=recommendation["selected_choice"],
            confidence=recommendation.get("confidence", {}).get("level"),
            timestamp=datetime.now().isoformat()
        )
    
    def log_red_line_violation(self, choice_id: str, red_line: str, enforceable: bool):
        logger.error(
            "red_line_violation_detected",
            session_id=self.session_id,
            choice_id=choice_id,
            red_line=red_line,
            enforceable=enforceable,
            timestamp=datetime.now().isoformat()
        )
```

| Term | Definition |
|------|------------|
| **ADIE** | AI Decision Intelligence Engine |
| **AHP** | Analytic Hierarchy Process |
| **BATNA** | Best Alternative to a Negotiated Agreement |
| **Design Tree** | Model where decisions branch into dependent decisions |
| **Emergent Questioning** | Questions generated from frontier, not predetermined |
| **Epistemic Halt** | Protocol for LLM to ask user when information is missing |
| **Facts vs. Decisions** | LLM answers facts; user answers decisions |
| **Frontier** | Set of decisions whose prerequisites are all settled |
| **Hidden Leverage** | Leverage user has but doesn't know about |
| **Leverage Map** | Complete inventory of all leverage in a decision |
| **Leverage Multiplier** | Factor adjusting utility based on applicable leverage |
| **Leverage Strength** | 1-5 scale measuring power of a leverage point |
| **Leverage Trajectory** | How leverage is changing over time (increasing/decreasing) |
| **Minimax** | Decision rule minimizing maximum loss |
| **Pareto Efficiency** | State where no one can be better off without making someone worse off |
| **Red Line** | Outcome that is absolutely unacceptable |
| **Red Line Enforceability** | Whether user has leverage to actually maintain a red line |
| **Six Leverage Domains** | Structural, Negotiation, Psychological, Resource, Informational, Positional |
| **ZOPA** | Zone of Possible Agreement |
